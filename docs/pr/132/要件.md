### #104 project-index 自身の配信元の検索の対象とメタデータ

- 検索の対象を、setup の手順 3 の既定（`**/*`。`.git`・`node_modules`・`.claude/worktrees` の下と、Git が無視するファイルは除く）に合わせる
  - develop の Git 管理のファイルのうち、`docs/pr/` を除いて対象に入っていないファイルは 93 件（`src/project_index/` の 33 件・`content/prompts/` の 15 件・直下の設定と `README.md`・`CLAUDE.md`・各フォルダの `README.md`・`schemas/`・`templates/`・`typings/` など）
  - `project-index files` が記載しないファイル（バイナリ・空のファイル・`*.local.*`）は対象に入れない
  - `content/prompts/` の YAML は、プロンプトの行（`templates/project-index.yaml` の `prompts` の行）の文書として 1 つだけ配信し、管理用の YAML の行に記載しない
- 既存の管理用の YAML（`src/files.yaml`・`tests/files.yaml`・`plugins/project-index/files.yaml`・`docs/guide/files.yml`）の行のメタデータを、setup の手順 4 の付け方（段階的に中身を参照して付ける・`project-index skew` で偏りを洗い出す）で見直す
  - `docs/guide/files.yml` の 15 行は `name`・`description` を持たない
- 見直した後に `project-index checkpoint` で確認の時点を記録し、`check_project` で索引の同期の件数（管理用の YAML に無いファイル・ファイルが無い行・`metadata` の列が無い文書）が 0 であることを確認する
- ほかの配信元（dev-docs・knowledge・ai-monitor・shuhdev-gateway・claude-balancer・alias-inject・rule-inject・aituber・mdmark・voice-paste・gui-support・mindstella・observability）ごとに、検索の対象とメタデータの見直しの Issue をそれぞれのリポジトリへ起票する

`未確定`: PR ドキュメント（`docs/pr/`）を検索の対象に入れるか（決める段: 実装のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `docs/pr/` を対象に入れる | setup の既定（`**/*`）と一致し、過去の PR の要件・計画も検索できる | 519 件の行とメタデータが増え、ログ・スクリーンショットの行が検索の結果に混ざる |
| B | `documents[].exclude` で `docs/pr/` を対象から除外する | 検索の結果が今の設計書・公開ドキュメント・コードに絞られる | setup の既定と違う値を持ち、過去の PR の経緯は検索できない |

推奨: B

PR ドキュメントは作業 PR ごとの記録で、決定した内容は設計書・公開ドキュメントへ反映されるため、検索の対象に入れても今の仕様を探す役に立たない。

### #71 「読み直し」「読み直す」の文言

- develop の `docs/pr/` を除く 88 ファイル・411 箇所の「読み直し」「読み直す」（「読み直さない」「読み直した」を含む）を、「再読み込み」（`reload`）の言い方に修正する

- `src/project_index/features/sources/registry.py` の describe の警告の `fix` と、ログの文言（`admin/service.py`・`registry.py`）は、同じ文言を記載する設計書 `docs/module/MOD-69.py.yaml`・`docs/module/MOD-10.py.yaml` と同じ commit で修正する
