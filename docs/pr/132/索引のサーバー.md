## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 検索の対象 | `project-index.yaml` の `documents[]` を、`docs/pr/` を除いた Git 管理のファイルが全ていずれかの行の文書になる構成にする。対象外の 93 件は、管理用の YAML の行の追加か、`content/prompts/` のプロンプトの行の追加で対象に入れる | `docs/pr/` を入れるかは `未確定`（[要件](./要件.md)） |
| 管理用の YAML の配置 | 直下の設定・`schemas/`・`templates/`・`typings/`・`content/` などの管理用の YAML の配置先と行の分け方は、setup の手順 4 の `project-index files` の結果を基に実装で決め、reviewer の確認を受ける | - |
| メタデータ | 既存の行と追加する行のメタデータを、setup の手順 4 の段階（目次のページ → `project-index outline` → 見出しの直下の段落 → 文章 → 全文）で改めて付け、`project-index skew` の出力ごとに見直す | 変えない行は今の値のまま |
| 確認の時点 | 管理用の YAML ごとに `project-index checkpoint` で記録する | - |
| 文言 | 「読み直し」「読み直す」を「再読み込み」に修正する。設計書は `write_docs` の `text_edits`、コード・テストと Markdown は Edit で修正する | 識別子・文言を比べるテストは変えない |
| ほかの配信元の Issue | 配信元ごとの対象外の件数（#104 の表）を添えて、見直しの Issue をそれぞれのリポジトリへ起票する | 起票先が AI Monitor の監視対象でないリポジトリは、起票の手段を実装で決める |
