## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 削除の前の検査 | `delete_docs` で、ファイルを削除する前に、`targets` の文書を全て除いた配信元のエージェントフローで全ての `type: skill` の SKILL.md を組み立てられるかを確認し、`ref` が解決できなくなるときは削除を断る | `未確定`（決める段: インターフェース定義設計） |
| 断ったときの返却 | `ValidationFailedError`（`atomic: false` は該当する `targets` の `failed`）で、参照しているエージェントフローの `id` と解決できなくなる `ref` を違反に入れる | 例外の名前は設計の工程で確定する |
| 参照元ごと削除 | 参照しているエージェントフローも同じ `targets` にあれば断らない | - |
| 対象外の削除 | エージェントフロー以外の種類と、どの `ref` からも指されないエージェントフローは今までどおり削除する | - |
| 処理時間 | `script_timeout_sec` と書き込みの期限の中で終わる | [非機能要件](https://github.com/shuhei1101/project-index/blob/9d95b0f/docs/nonfunctional/NFR-1.yaml) のスクリプトの制限時間 |

検査の仕組みの案:

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `validators[].on` に削除の時点（`delete`）を追加し、`delete_docs` が削除の時点の `validators[]` に削除する文書の ID を指定する。`project-index skill-md --check` に削除の入力を受けるモードを加える | 配信元の設定で検査を選べ、種類ごとの検査の約束に統一できる | `validators[]` の約束（標準入力に文書の YAML 1 件）に削除の入力の構造を追加する必要がある |
| B | `delete_docs` の service.py に、`agent_flow` の `ref` の参照を確認する処理を直に持たせる | 約束を増やさない | 配信元の設定に依らない、エージェントフロー専用の処理が削除の共通の処理に入る |

推奨: A

`write_docs` の書き込み前の検査と同じく配信元の設定の `validators[]` で選べ、SKILL.md の組み立ての処理を `project-index skill-md` の 1 か所に保てる。
