# 要件

## 要望

- `delete_docs` で、配信元に残る `type: skill` のエージェントフローが工程の `ref`（`{id}#steps[{name}]`）で指すエージェントフローを削除する操作を、ファイルを削除する前の検査で断る
  - 断った結果に、参照しているエージェントフローの `id` と `ref` を入れる
  - 断ったときは、削除の対象のファイル・参照元・SKILL.md のどれも変わらない
  - 1 回の `targets` で、参照しているエージェントフローも一緒に削除する場合は、残るエージェントフローだけで SKILL.md を組み立てられるかで判定する
- `ref` の参照先でないエージェントフローと、エージェントフロー以外の種類の削除は、今までどおり削除できる
- 検査の仕組み（`validators[]` の削除の時点・`project-index skill-md --check` の削除のモード 等）は設計の工程で決める
