### #31 クラス図の click の ID の参照

対象は `docs/module/` の 77 文書・411 行の `click {ノード} href "./MOD-{n}.py.yaml#{見出し}"`（develop、`docs/pr/` を除く `grep -rn 'click .* href'`）。

描画の対応（develop で確認）:

| 描画 | `id:` の参照を解くか |
| --- | --- |
| dev-docs の画面のサーバー（shuhei1101/dev-docs の `src/dev_docs/features/convert/inline.py`） | Markdown のリンク `[名前](id:{ID}#{項目})` だけを解く。クラス図は `render_mermaid` が読み取れず Mermaid のまま渡し、`click` の href の `id:` は解かない |
| dev-docs の移し替え（`schemas/conversions/v0.4.0.py`） | `click … href "…"` のパスを `id:{ID}#{項目のパス}` へ書き換える手順を持つ |

描画の対応: Mermaid の `click` の href の `id:` の参照をリンクへ解く対応を [shuhei1101/dev-docs#196](https://github.com/shuhei1101/dev-docs/issues/196) に起票して依存に置き、この作業 PR では 410 行の href を `id:{ID}#{項目のパス}` へ書き換える。
項目のパスは、リンク先の設計書で見出しの文字列を `title` か `x-key` の値に持つ要素のパス（`data_models[SessionKey]` など）で、同じ見出しの要素が入れ子にもあるときは最上位の要素を指す。

### #30 タグ・エイリアス・用語の付与

| 対象 | 変更 |
| --- | --- |
| 文書のスキーマ（`schemas/*.schema.yaml`） | 文書の `tags`（`name` と `main`）と `aliases` を任意のキーで持つ。共通の定義は `common.schema.yaml` の `$defs` に置き、種類ごとのスキーマから参照する |
| `project-index.yaml` の設計書の種類の行 | `metadata` に `tags: tags[].name`・`main_tags: tags[main].name` を足し、`alias_type: doc` を持つ |
| `docs/guide/files.yml` | 公開ドキュメントの Markdown の行に `tags` を持つ |
| 用語集 | `alias_type: term` の種類（スキーマ・`documents[]` の行・用語の文書）を新しく作り、`docs/guide/用語集.md` の用語をその文書へ移す |
| 設計書・公開ドキュメント | `action:`・`topic:`・`tool:` のタグを付け、`main` を 1 つにする。付ける前に `group_by: tags` で使用されているタグを使い回す。エイリアスと用語は判定フローチャート『エイリアスの登録』『用語の登録』で判定して登録する |

`未確定`: 用語集の種類の配置先と形式（決める段: 実装。判定フローチャート『ドキュメント配置判定』『データ化判定』で決める）

| 案 | 内容 |
| --- | --- |
| A | `docs/glossary/*.yaml`（1 用語 1 文書、スキーマ `schemas/glossary.schema.yaml`）。`docs/guide/用語集.md` は用語集の文書の一覧を描く目次にする |
| B | `docs/guide/用語集.yaml`（全用語を `records` の配列で 1 ファイルに持つ） |

推奨: A

用語ごとに `name`・`aliases`・`description` を持ち、`search_docs` の `term` が 1 文書を返す形が、既存の種類の行の持ち方（1 ファイル 1 文書）と揃うため。
