# 要件

## 要望

`write_docs` の `create` で、種類のスキーマが ID のキーを持たないとき、操作の `id` を省いて `new_path` を指定すると、正規化した `new_path`（配信元の直下からのパス）を文書の ID にして作成する。

| 指定 | 振る舞い |
| --- | --- |
| ID のキーを持たない種類で、`id` を省いて `new_path` を指定する | 正規化した `new_path` を文書の ID にし、`data` に `id` を加えずに作成する（作成後の `search_docs` が返却する ID と同じ） |
| ID のキーを持つ種類 | 今と同じく、`data` の ID か `ids.format` から ID を決める（`new_path` は配置先だけに使用する） |
| `new_path` を省く | 今と同じ |
| 正規化した `new_path` を ID にした文書が既にある | 何も書き込まずに `InvalidArgumentError` で断る |

- `commit` を指定した `create` でも使用でき、直コミットの判定は今と変えない
- aituber の `portrait_definition`（行の `paths` が `portrait/*/definition.yaml`）で、`portrait/kotonoha-akane/definition.yaml` を ID にして作成できる
- 正常系のテストに、`data` に `id` を持たない種類（`chars/c1/definition.yaml` のパスに作成する種類）の作成を含める
