## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 作成機能 | 種類のスキーマが ID の列（`metadata.id`、既定 `id`）をプロパティに持たず、`id` を省いて `new_path` を指定した `create` は、正規化した `new_path` を ID にする | `records` を持たない行だけ（`records` の行は `new_path` を受けない） |
| 作成機能 | ID を `new_path` から作ったときは、`data` の ID の列へ ID を入れない | 読み込みが `fallback_id` でパスを ID にするため、作成後の ID と一致する |
| バリデーション | `new_path` を ID にした文書が既にある・`new_path` の違反（配信元の外・`paths` に該当しない・既にある）は今と同じ `InvalidArgumentError` | - |
| 直コミット | `commit` を指定した `create` でも同じ ID と配置先で書き込み、コミットする | 判定は変えない |
| SC-7・IF-6・MOD-84・MOD-85 | ID のキーを持たない種類の `create` で `new_path` を ID にする正常系と、ID の作り方の制約を追加する | - |
| ガイド | 文書の MCP のガイドの `create` の `new_path` と `Operation.id` の説明に、ID のキーを持たない種類では `new_path` を ID にすることを記載する | - |
| 既存機能への影響 | ID のキーを持つ種類の `create`・`new_path` を省いた `create`・`rename` は変えない | 既存の単体・結合テストで回帰を確認する |
