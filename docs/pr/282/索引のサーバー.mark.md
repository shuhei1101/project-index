## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 改名の参照元の書き換え | 改名 1 件の間、ファイルごとに読み込んだ結果を使い回し、改名前の ID・パスの文字列を本文に持たないファイルは YAML として読み込まずに飛ばす | 書き換える参照元・書き換えの結果・`references` の返却は変えない |
| 書き込みの後の通知の判定 | 1 回の要求でワークツリーを配信元のフォルダごとに 1 回だけたどり、全ての管理用の YAML の行で再利用する | [要件](./要件.mark.md) |
| 実行スロット | `POST /_admin/post-write` を、文書の MCP と別の専用の実行スロットで動かす | 本数は非機能要件で決める |
| 実行中の要求 | 実行スロットで動いている要求の記録（ツール・配信元・経過秒）を持ち、管理の MCP の `status` で返却する | 管理の MCP は自分の実行スロットで動くため、文書の MCP の実行スロットが埋まっていても応答する |
| 既存の振る舞い | 書き込みの後の通知の対象と文面、`status` の既存の項目は変えない | 破壊的変更なし |
| テスト | 改名で読み込む回数、通知の判定でたどる回数、実行スロットの分離（文書の MCP の実行スロットが全て埋まっている間も `POST /_admin/post-write` が応答する）、`status` の実行中の要求を確認する | 単体と結合 |
