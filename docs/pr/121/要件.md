#117 の 4 件は、テストの期待か実装のどちらが正しいかをインターフェース定義の結合テストの記載と突き合わせて決め、正しくない側を修正する。

| テスト | 原因 | 修正の向き |
| --- | --- | --- |
| `test_describe.py::test_normal_when_rechecked_after_write` | [#92](https://github.com/shuhei1101/project-index/pull/92) で `body_file` の行の `create` に `@body` が必須になったが、テストは `data: {path: extra0.py}` だけを送る | テストの `create` に `@body` を追加する |
| `test_search_docs.py::test_error_when_unexpected` | [#94](https://github.com/shuhei1101/project-index/pull/94) でリビジョンの書き出しが 20 秒を超えると `RevisionExportTimeoutError` を返すようになり、偽の git が `archive` で 25 秒待つ準備では `GitError` に届かない | テストの準備を、時間切れより先に `git archive` が失敗する偽の git にする。インターフェース定義 IF-2 の結合テストの記載も合わせる |
| `test_describe.py::test_normal_when_warned` | 1 回目だけ警告の `- sample: 管理用の YAML に無いファイルが 1 件` の行が無い（ログには出ている）。回し直すと pass し、ランナーでは pass した。原因は未特定 | 原因を切り分け、テストの待ち方か警告を集める処理を修正する |
| `test_try_convert.py::test_error_when_invalid_config` | `assert "1" in result.text` が、違反の件数ではなく一時フォルダのパスの `1` に当たって pass している | 応答の本文に違反の件数を確かめる期待へ直す |

#118 は、往復編集の書き出し（`src/project_index/shared/yaml_io.py` の `dump_roundtrip`）が字下げを固定値 `YAML_INDENT`（`mapping: 2`・`sequence: 4`・`offset: 2`）で書くことが原因。
読み込んだ元の文字列から、配列の字下げ（`- ` を親のキーと同じ列に置くか、字下げするか）を検出し、書き出しで同じ字下げにする。
`YAML_INDENT` は `write` のほかに `migrate`・`settings`・`admin`・`checkpoint` も往復編集の書き出しで使用するため、修正は共通の `dump_roundtrip` に入れ、全ての往復編集の書き出しで元のファイルの字下げを維持する。
元の文字列が無い作成（`op: create`）は、今の `YAML_INDENT` で書く。
