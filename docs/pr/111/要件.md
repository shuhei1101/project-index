# 要件

## 要望

`project-index.yaml` に `nav` を記載し、dev-docs の画面のこの配信元のタブとサイドバーを、規約『開発ドキュメントのナビゲーション』（knowledge の `dev-docs-navigation`）に従って並べる。

| 対象 | 終了の条件 |
| --- | --- |
| タブの並び | 規約の順（はじめに・使い方・設計書・規約・コード・リファレンス・用語集）のうち、この配信元に文書があるタブだけが左から並ぶ |
| タブの数 | 7 件以下。設計書の種類ごとのタブが無く、タブ「設計書」1 つにまとまる |
| サイドバー | 各タブの文書が `group` か `auto.group_by` でグループにまとまり、入れ子は 2 階層まで。設計書は種類がグループになる |
| グループの中の並び | 手順の順か重要さの順。名前の順は名前を知っている文書を探す一覧（用語集など）だけ |
| 目次 | `documents[]` の `index` の行の文書（フォルダの目次）が、どのタブにもサイドバーにも出ない |
| 内部のファイル | 閲覧者が参照しない内部のファイル（各フォルダの `README.md`・目次の代わりの Markdown）が、タブとサイドバーに出ない |
| 文書の ID と本文 | `documents[].id`・文書の ID・本文の参照を変えない |
| 画面での確認 | 修正後の dev-docs の画面を、タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないこと・文書をスクロールした状態のスクリーンショットで確認し、reviewer の確認を受ける |

公開ドキュメントのタブ（はじめに・使い方・リファレンス）は、`files_guide` の行の文書を `category` で分ける。
用語集のタブは `glossary` の行（`records: terms`）の用語を並べる。

## テスト結果

単体・結合テストは実行していない。
変更は配信元の設定（`project-index.yaml` の `nav`）だけで、`src/`・`plugins/`・`tests/` のコードを変えず、対応する単体・結合テストが無い。
