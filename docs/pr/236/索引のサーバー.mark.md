## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の切り分け | 本番と同じ配信元・worktree の数で、複数のクライアントから時間切れとやり直しを含む呼び出しを続ける再現を作り、Issue の候補 No.1〜5 と設計書・コードから見つかる候補を 1 つずつ除外して所要時間と RSS を測る | PoC 検証で行い、結果を `## PoC 結果` に残す |
| キャッシュの索引 | ファイルのキャッシュのキーを、読む場所ごとに直前に見たキーと、パスごとに引けるようにし、`_discard_files`・`invalidate` がキャッシュ全体をたどらないようにする | PoC 結果の核心部 |
| 捨てられた要求 | 変えない | PoC で、捨てない変種は待ちが伸びるだけ、`asyncio.shield` を外す変種は接続断が増えた |
| 管理の MCP | 専用の実行スロットで動かし、文書の MCP の実行スロット・裏の処理の詰まりに関係なく `status`・`restart` が応答する | PoC で成功条件 No.4 を満たした |
| 保持するもの | 稼働時間とともに増えるもの（リビジョンの読み込みの結果・worktree のたどった結果など）に上限か捨てる時点を持たせる | 切り分けで RSS の増加が劣化の原因と分かった場合 |
| 記録 | 要求ごとの実行スロットの待ち・排他の待ち・処理の時間と、実行中・待ち中の処理の数・RSS を定期的にログへ記録する | 要件 No.4 |
| 非機能要件 | 実行スロットの数・保持の上限など、追加する値を非機能要件に導出つきで記載する | - |

## PoC 結果

結論: **不成立**（PoC PR [#237](https://github.com/shuhei1101/project-index/pull/237)、検証コードは [a5f98e5](https://github.com/shuhei1101/project-index/commit/a5f98e5)）。
原因の 1 つは特定できたが、修正を入れても本番の 4 倍の負荷では稼働時間とともに時間切れが増え、成功条件 No.3・No.5 を満たさなかった。

### 成功条件との突き合わせ

| No. | 成功条件 | 実測値 | 判定 |
| --- | --- | --- | --- |

| 2 | 取り除くと劣化が消える処理を特定する | 温まった呼び出しのたびに `_discard_files`・`invalidate` が `_files` 全体をたどり、使った worktree の数に比例して遅くなる。1 クライアントの計測で、他の worktree を 60 件読んだ後の呼び出しが 0.72 秒 → 0.08 秒 | 成立（ただし 4 倍の負荷では劣化が残る） |
| 3 | 修正後、1 時間以上回して全ての応答が 48 秒以内・worktree の読み込みが開始直後の 3 倍以内 | 71 分の実行で 10 分ごとの時間切れが 14 → 22 → 39 → 15 → 65 → 72 → 90 件。p50 は 0.6 秒 → 55 秒（打ち切り） | 不成立 |

### 核心部

`_files` のキーを、読む場所ごとに直前に見たキーと、パスごとに引けるようにして、全体をたどらないようにする（[store.py](https://github.com/shuhei1101/project-index/blob/a5f98e5/src/project_index/features/documents/store.py)）。

```python
def _discard_files(self, root: Path, kind_ids: set[str], seen_keys: set[_FileKey]) -> None:
    group = (root, frozenset(kind_ids))
    with self._lock:
        previous = self._poc_seen.get(group, set())
        for key in previous - seen_keys:
            self._files.pop(key, None)
            self._poc_by_path.get(key[0], set()).discard(key)
        self._poc_seen[group] = set(seen_keys)

def invalidate(self, paths) -> None:
    targets = set(paths)
    with self._lock:
        for path in targets:
            for key in self._poc_by_path.pop(path, set()):
                self._files.pop(key, None)
```

管理の MCP は `asyncio.to_thread` の既定の実行スロットではなく、2 本の専用の `ThreadPoolExecutor` で動かす（[admin.py](https://github.com/shuhei1101/project-index/blob/a5f98e5/src/project_index/server/mcp/admin.py)）。

#237 の diff の見どころ:

- `poc/degradation/load.py`・`run.sh`: 32 クライアント・毎分 45 回の呼び出しと、worktree を 2 分ごとに増やす負荷
- `poc/degradation/bench_warm.py`: 1 クライアントで温まった呼び出しの所要時間を測るベンチ
- `PI_POC_*` の環境変数: 変種の切り替え

### 方針からの逸脱

- 負荷は本番の 4 倍にしたが、修正前でも開始 10 分で p95 が 45 秒あり、稼働時間による劣化より先に処理能力の上限に当たっていた
- 裏の処理の関所の変種は、外す代わりに休ませない変種で測った
- 変種は 60 分でなく 30 分で測った
- worktree ごとの索引の変種と、1 クライアントのベンチを足した
