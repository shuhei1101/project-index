# 要件

## 要望

配信元の設定の `documents[]` の行に、SQLite のデータベースのファイル（配信元のフォルダからの相対パス。ワークツリーを指した検索でも配信元のフォルダのファイルを開く）と、表か SQL のビューの名前を記載できるようにする。
その行では、表の 1 行を 1 件の文書にして配信する。

- 共通のメタデータ（`id`・`name`・`description`・`tags` とエイリアスのキー）は、行の `metadata` の列名の対応で表の列から取得する。配列の値（`tags`・`aliases`）は JSON の配列の文字列の列から取得する
- 配信した文書は `search_docs` のタグ・種類・本文の条件、`describe` の種類の説明、`list_match_words` の別名の照合（`alias_type` を持つ行）の対象になる
- `describe` は、行に記載した列の説明を種類のスキーマの代わりに返却する
- `write_docs`・`delete_docs` は、SQLite の行の種類の文書への書き込み・削除を、読み取り専用である理由を添えて断る
- `list_changes` は、SQLite の行の種類の文書を対象から除外する（履歴を持たないため）
- `check_project` は、SQLite の行のファイル・表・列の対応を検証し、欠けを違反として返却する
- 既存の `documents[]` の行（ファイルと `records`）の振る舞いは変えない
- 行の多い表（発話・セリフ）は、行に記載する `where`（配信する行の条件）・`order_by`（行の並び）・`limit`（読み込む行の上限。既定 1000 行）で絞り、上限を超えた分は配信せずに `describe` と `check_project` で通知する
- SQLite の表の行は、呼び出しごとにファイルと WAL のファイルの更新日時とサイズを比べ、変わったときだけ再読み込みする
- `ref`（リビジョン）を指定されても、SQLite の表の行は今のファイルの行を返却し、結果に今の内容である旨を添える
