## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元の設定 | `documents[]` の行に SQLite のファイル・表かビュー・共通のキーと列の対応・列の説明を記載でき、ファイルと `records` の行と排他にする | キーの名前と構造はデータ設計で決める |
| 文書の作成 | 表の 1 行を 1 件の文書にし、`metadata` の列名の対応で共通のメタデータを取得する。JSON の配列の文字列の列は配列にする | SQLite は読み取り専用で開く |
| 行の多い表 | 要件の `未確定` の論点（推奨: A。`where`・`limit` と上限超過の警告） | `未確定` |
| 読み込む時機 | 要件の `未確定` の論点（推奨: A。ファイルの更新を検知して再読み込みする） | `未確定` |
| `ref` の扱い | 要件の `未確定` の論点（推奨: A。今のファイルの行を返却し、その旨を添える） | `未確定` |
| `write_docs`・`delete_docs`・書き込みの API | SQLite の行の種類の文書を操作の対象にしたら、読み取り専用である理由のエラーで断る | - |
| `list_changes` | SQLite の行の種類の文書を対象から除外する | - |
| `check_project` | ファイルが無い・表やビューが無い・対応の列が無いを違反にする | - |
| エラー返却 | 起動時に SQLite のファイルを開けない行は、その配信元の他の行の配信を止めずに状態の警告にする | 既存の読み込みの誤りの扱いに合わせる |
| 既存機能への影響 | ファイルと `records` の行の振る舞いは変えない | - |
| 性能 | 読み込む行の上限の既定を非機能要件の決定値として持つ | 値はデータ設計で決める |
