## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元の設定 | `documents[]` の行に `sqlite`（`file`・`table`・`where`・`order_by`・`limit`・`columns[]`）を記載でき、ファイルと `records` の行と排他にする。共通のキーは既存の `metadata`・`alias_type` で対応する | 設定の設計書 CFG-1 |
| 文書の作成 | 表の 1 行を 1 件の文書にし、`metadata` の列名の対応で共通のメタデータを取得する。JSON の配列の文字列の列は配列にする | SQLite は読み取り専用で開く |
| 行の多い表 | `where`・`order_by`・`limit` で絞り、上限を超えた分は配信せずに `describe()` の注意と `check_project` の警告で通知する | - |
| 読み込む時機 | 呼び出しごとにファイルと WAL のファイルの更新日時とサイズを比べ、変わったときだけ再読み込みする | 文書の検索 IF-2 の制約 |
| `ref` の扱い | `ref` によらず今のファイルの行を返却し、`notes` に今の内容である旨を添える | 文書の検索 IF-2 の制約 |
| `write_docs`・`delete_docs`・書き込みの API | SQLite の行の種類の文書を操作の対象にしたら、読み取り専用である理由のエラーで断る | - |
| `list_changes` | SQLite の行の種類の文書を対象から除外する | - |
| `check_project` | ファイルが無い・表やビューが無い・対応の列が無いを違反にする | - |
| エラー返却 | 起動時に SQLite のファイルを開けない行は、その配信元の他の行の配信を止めずに状態の警告にする | 既存の読み込みの誤りの扱いに合わせる |
| 既存機能への影響 | ファイルと `records` の行の振る舞いは変えない | - |
| 性能 | 読み込む行の上限の既定 1000 行を非機能要件の決定値として持つ | 非機能要件 NFR-21 |
