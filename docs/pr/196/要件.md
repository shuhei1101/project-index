# 要件

## 要望

| 番号 | 終わりの条件 |
| --- | --- |
| 1 | Git 管理外の配信元（`storage.type: disk` を含む）で、配信元の設定に日時を付けない指定をした種類の文書を、`write_docs` の `create`・`update`・`replace`・`rename`・`replace_text` と、`rename` に追随する参照元の書き換えで `created`・`updated` を追加せずに書き込める。追加するかは書き換える文書の種類の指定で決める。指定を省いた配信元は今どおり追加する |
| 2 | `body_file` を指定した行で、`body_file` の列を持たない・値が空の要素を、本文のファイルを持たない文書として `search_docs`・`trace_related`・読み取り API で参照でき、`write_docs`・`delete_docs` で作成・更新・削除できる。列の値があって指すファイルが無い・配信元の外を指す要素は、今どおり `missing_body_file` にする |
| 3 | 1 回の `search_docs` の結果の警告に、同じファイルの同じ理由の行が要素の数だけ並ばない |

- 確認方法: MindStella の話し合いのフォルダ（`/home/shuhei2441/repo/tmp/nandemo-kaiwa`、配信元 `mindstella-nandemo-kaiwa-b31827`）の設定に日時を付けない指定を記載し、Issue の表の 2 つの操作（`dry_run: true`）が検査に通ることと、`search_docs` の件数に本文を持たない 301 件が加わり警告が並ばないことを観測する
- 本文のファイルを持たない要素の本文・ID・名前は、`body_file` を持たない `records` の行の要素と同じにする（本文は要素を YAML に書き出した文字列、ID の既定は `{管理用の YAML のパス}#{位置}`、名前の既定は ID）

`未確定`: 日時を付けない指定を記載する場所（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `documents[]` の行のキー | スキーマは種類ごとに持つので、種類ごとに決められる | 全ての種類で付けない配信元では行の数だけ記載する |
| B | 配信元の設定の最上位のキー | 1 か所の記載で済む | 種類ごとに変えられない |

推奨: A

日時を受け付けるかは種類のスキーマの `additionalProperties` で決まり、スキーマと同じ単位で指定できる方が設定とスキーマが食い違わない。

`未確定`: 本文のファイルを持たない要素への書き込みの扱い（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `create` は `data` に `body_file` の列も `@body` も無ければ本文なしで作り、どちらか一方だけなら今どおり違反にする。`update` で本文のファイルを持たない要素に `body_file` の列と `@body` を同時に指定したときだけ本文のファイルを作り、片方だけは違反にする |
| B | 本文のファイルを持たない要素への `@body`・`body_file` の列の変更は全て違反にし、本文を付けるときは要素を作り直す |

推奨: A

本文が任意の種類では、後から本文を追加する操作が普通に起きる。作り直しは ID と関連を保てない。
