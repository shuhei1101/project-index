# 要件

## 要望

端末の設定の API で、配信元の行を 1 行ずつ追加・変更・削除できるようにし、同時の書き換えを後から書き換えた側が気づけるようにする。

| 要件 | 終わりの条件 |
| --- | --- |
| 1 行の変更 | 配信元の `id` で指した 1 行のキーだけを書き換え、ほかの行と、その行の送信しなかったキーはファイルの今の値のまま残る |
| 1 行の削除 | 配信元の `id` で指した 1 行だけを `sources[]` から削除し、ほかの行は変わらない |
| バージョンの返却 | 端末の設定の取得と、全ての書き換え（1 行の追加・変更・削除、丸ごとの保存）の応答が、端末の設定の内容のバージョン（ファイル全体の内容のハッシュ。`version` キーの設定のバージョンとは別）を返却する。利用者がファイルを手で書き換えたときもバージョンが変わる |
| バージョンの照合 | 書き換え（丸ごとの保存と 1 行の追加は、要求にバージョンがあるとき）が、要求のバージョンとファイルの今のバージョンを照合し、違えば書き換えずに 409 を返却する |
| 書き換えた行の状態 | 1 行の追加・変更の応答が、その行の配信元の状態（`serving`・`not_served`・`disabled` など）を返却し、呼ぶ側が配信の始まりを確認できる |
| 読み直しの範囲 | 1 行の追加・変更・削除の後に読み直す配信元を、その行の配信元に限り、ほかの配信元の配信を止めない |
| 端末のほかのプロセスからの呼び出し | `Origin` も `Sec-Fetch-Site` も持たない要求で、全ての書き換えを呼べる（今の `require_same_origin` のまま） |

`id` を省いた行は、1 行の変更・削除では、配信元の設定の `name` から求まる配信元の ID（`entry_source_id`）で指す。

内容のバージョンは、1 行の変更・削除では必須（無ければ 400）にし、丸ごとの保存と 1 行の追加では `expectedVersion` を送信したときだけ照合する。
dev-docs の設定の画面がバージョンを送信するようになるまで、画面からの保存を断らないため。
