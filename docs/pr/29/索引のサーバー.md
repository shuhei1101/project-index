## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 1 行の変更 | `PATCH /settings/sources/{id}` で、送信したキーだけをその行に重ね、送信しなかったキーはファイルの今の値で残す | 行が無ければ 404 |
| 1 行の削除 | `DELETE /settings/sources/{id}` で、その行だけを `sources[]` から削除する | 行が無ければ 404 |
| 行の指し方 | 行の `id`、`id` を省いた行は配信元の設定の `name` から求まる配信元の ID で指す | 1 行の追加の同じ id の判定と同じ求め方 |
| 端末の設定の内容のバージョン | 端末の設定のファイルの内容のハッシュを、取得と全ての書き換えの応答で返却する。書き換えの要求では `write_docs` と同じ `expected_version` で受ける | 利用者が手で書き換えたときも変わる。`version` キーの設定のバージョンとは別 |
| バージョンの照合 | 書き換えの要求のバージョンを、ロックを取った後にファイルの今のバージョンと照合し、違えば書き換えずに 409 と今のバージョンを返却する | バージョンを送信しない要求の扱いは `未確定`（[要件](./要件.md)） |
| 書き換えた行の状態 | 1 行の追加・変更の応答に、その行の配信元の状態と新しいバージョンを返却する | - |
| 読み直しの範囲 | 1 行の追加・変更・削除の後は、その行の配信元だけを読み直し、ほかの配信元の配信を続ける | 丸ごとの保存は今のとおり全ての配信元を読み直す |
| オリジンの確認 | 1 行の変更・削除にも `require_same_origin` を適用する | 端末のほかのプロセスは `Origin` を持たないため呼べる |
| エラー返却 | 409（バージョンの不一致）・404（行が無い）・422（スキーマ違反）を `application/problem+json` で返却する | 1 行の追加の 409（同じ id の行がある）と区別できるようにする |
