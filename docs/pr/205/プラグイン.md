## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| PostToolUse のフック | `hooks.json` に PostToolUse を追加し、新規のフック `hooks/post_tool_use.py` で、書き込んだファイルが配信元のフォルダの下にあり、管理用の YAML・配信元の設定でなく、そのセッションで未通知のときだけ `additionalContext` で通知する | 判定は索引のサーバーの `POST /_admin/post-write`（[IF-35](https://github.com/shuhei1101/project-index/blob/b42688c/docs/interface/IF-35.yaml)）に問い合わせる（[IF-36](https://github.com/shuhei1101/project-index/blob/b42688c/docs/interface/IF-36.yaml)） |
| 対象のツール | Write・Edit は `tool_input.file_path`、MCP のツールは引数の文字列の値のうち配信元のフォルダの下のパス。文書の MCP の `write_docs`・`delete_docs` は対象にしない | Bash での作成・削除・改名はスコープ外 |
| 通知の 1 回 | 索引のサーバーが、セッション ID ごとに通知したパスを記録し、記録にあるパスには通知しない | 索引のサーバーの計画書 |
| 通知の文面 | 管理用の YAML の行の有無で文面を分け、メタデータを付ける基準を文書の MCP で取得する引数を添える。`alias_type` の行・rule-inject の索引があるときだけ 1 行ずつ追加する | 文面は `content/prompts/` のプロンプトにするかをモジュール構成設計で決める |
| 失敗の扱い | 入力を解析できない・配信元を検索できない・記録を保存できないときは、何も出力せずに終了コード 0 で終了する | 書き込みを止めない |
| 指摘を登録するスキル | `skills/` に新規のスキルを追加し、SKILL.md には手順のページを文書の MCP で取得して進めることと確認の方法だけを記載する。手順は `docs/guide/` に新規作成するページに配置する | スキル名は `/project-index:feedback`（確認ログ） |
| 登録先の判定 | rule-inject・alias-inject の端末の設定のファイルとプラグインの有無で、選択肢に出す登録先を決める | 緩い依存。両方が無い環境では project-index と登録しないだけを出す |
| 登録先の設定の作成 | 既定の置き場所に配信元の設定・rule-inject の索引・用語の YAML が無ければ雛形から作り、各ツールの端末の設定に登録する | 雛形は `templates/` に配置する。既定の置き場所は `~/.local/share/feedback/`（確認ログ） |
