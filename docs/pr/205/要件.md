### #199 の確定した内容

- フックは PostToolUse で、通知は `additionalContext` で文脈に追加する。終了コードは常に 0 で、ツールの結果を変えない
- 対象のツールは Write・Edit と、引数の文字列の値に配信元のフォルダの下のパスを持つ MCP のツール。文書の MCP の `write_docs`・`delete_docs` は管理用の YAML を自分で扱うため対象にしない
- 通知の文面は、管理用の YAML に行が無いファイル（行を追加する）と、行があるファイル（中身が変わって名前・概要文・タグ・関連が合わなくなったときだけ修正する）で分け、どちらも [メタデータを付ける基準](https://github.com/shuhei1101/project-index/blob/1ad0764/docs/guide/%E3%83%A1%E3%82%BF%E3%83%87%E3%83%BC%E3%82%BF%E3%82%92%E4%BB%98%E3%81%91%E3%82%8B%E5%9F%BA%E6%BA%96.md) を文書の MCP で取得する引数を添える
- エイリアスとルールの索引は、配信元の中身だけで判定して文面に 1 行を追加する。配信元の設定に `alias_type` を持つ行があればエイリアスの 1 行、配信元のフォルダに rule-inject の索引があれば索引のエントリの 1 行。alias-inject・rule-inject のコードは呼ばない
- フックは Python の標準ライブラリだけで動き、配信元を検索できないとき（サーバーが止まっている・端末の設定が無い）は何も出力せずに終了する
- 配信元のフォルダの下でも `documents[].paths` に該当しないファイルには通知しない。範囲に入れるかの判断はスキル `setup` の突き合わせに任せる（配信元のフォルダには範囲の外の生成物やログが多く、通知が増えると他の通知が埋もれるため）
- 確認方法: 配信元のフォルダの下のファイルを Write で作った後と Edit で書き換えた後に、文脈に通知が 1 回だけ追加され、同じセッションで同じファイルをもう一度書き換えても追加されないことを観測する。管理用の YAML・`project-index.yaml` を書き換えたときと、配信元の外のファイルを書き換えたときに通知が出ないことを観測する

### #202 の確定した内容

- スキルはプラグイン `project-index` の `skills/` に追加し、手順は [#201](https://github.com/shuhei1101/project-index/pull/201) のスキル `setup` と同じく `docs/guide/` のページに配置して文書の MCP で取得して進める
- 登録の基準（どの指摘をルール・エイリアス・文書のどれにするか）と抽象化の仕方は、手順のページに配置する
- 確認は AskUserQuestion を使用できる環境では AskUserQuestion で、使用できない環境では番号つきの選択肢を文で示して行う
- rule-inject・alias-inject が入っているかは、それぞれの端末の設定のファイルとプラグインの有無で判定し、入っていない登録先は選択肢に出さない
- プラグインと端末の設定のファイルの両方があるときだけ入っているとみなす。片方だけのときも選択肢に出さず、そのツールの用意（global-setup）を案内する。スキルはツールの端末の設定のファイルそのものを作らず、既にあるファイルへ置き場所の行を追加する
- 確認方法: rule-inject・alias-inject が入った端末で、指摘を 3 件含む会話の後にスキルを実行し、置き場所の確認が 1 回だけ出て、指摘ごとに案と登録先の確認が出ること、登録したルール・用語・文書が次のセッションで rule-inject の案内・alias-inject の用語・`search_docs` で検索できることを観測する。alias-inject を外した端末で、登録先の選択肢に alias-inject が出ないことを観測する

`未確定`: フックが書き込んだパスから配信元のフォルダを検索する方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
