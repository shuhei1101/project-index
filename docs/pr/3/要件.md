# 要件

## 要望

設計書も実装も無い project-index のリポジトリに、dev-docs から機能を移す後続の作業（[shuhei1101/dev-docs#114](https://github.com/shuhei1101/dev-docs/issues/114)）が前提にする土台を用意する。
新しい機能は作らない。

| 対象 | 用意するもの |
| --- | --- |
| アーキテクチャ図 | Issue 本文のコンポーネントの表（文書の MCP・管理の MCP・プラグイン・読み取りAPI・問い合わせ・書き込み・配信元と権限・索引・会話記録・スクリプトの実行）と、外部の利用者（Claude Code のセッション・AI Monitor と aituber のエージェント・dev-docs の画面のサーバー） |
| 非機能要件 | 動作環境（対応 OS・通信）。決定値は後の工程で決める |
| データの保存先（設定の設計書。モジュール構成設計で書く） | 端末の設定 `${XDG_CONFIG_HOME:-~/.config}/project-index/settings.yaml`・状態のフォルダ `${XDG_STATE_HOME:-~/.local/state}/project-index`・各リポジトリの配信元の設定 `project-index.yaml`・`project-index.local.yaml` |
| ドキュメントの骨格 | `dev/設計書/` と `docs/` の目次、設計書の Schema、テスト実行方法・開発コマンド、ルール索引、`CLAUDE.md`、`nav.project.yml`、dev-docs の配信元の設定 |
| パッケージの骨組み | uv で管理する Python 3.14 のパッケージ `src/project_index/` と起動の入口。実行時の依存（FastAPI・MCP（Streamable HTTP）・ruamel.yaml・jsonschema）は、それを使うコードと一緒に shuhei1101/dev-docs#114 で加える |
| プラグインの骨組み | Claude Code のプラグイン `plugins/project-index/` の `plugin.json` と、マーケットプレースの設定。MCP の接続・フック・スキルは shuhei1101/dev-docs#114 で加える |
| `README.md` | テンプレート『プロジェクトREADME』の見出し・1 行・ドキュメントサイトの URL |

コンポーネントの名前は、配信元・索引・会話記録・問い合わせ・読み取りAPI を使う。

## 影響するユースケース

| 種別 | ユースケース | 影響 | 依存 |
| --- | --- | --- | --- |
| 単一ユースケース | なし | なし（新しい機能を作らない。機能のシナリオは shuhei1101/dev-docs#114 で移す） | |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| dev-docs の機能・コード・設計書（分類『文書のMCP』『検索』『書き込み』など）の移植 | Issue 本文で後続の作業とされている | [shuhei1101/dev-docs#114](https://github.com/shuhei1101/dev-docs/issues/114) |
| dev-docs・alias-inject の配信元の設定のファイル名を `project-index.yaml` へ変える作業 | 各ツールのリポジトリの変更で、このリポジトリで完結しない。同じ内容が既存の Issue の決定 D-154 にある | [shuhei1101/dev-docs#114](https://github.com/shuhei1101/dev-docs/issues/114) |
| AI Monitor の設計書の検証のコマンド（`python -m ai_monitor.design_docs validate`）が `dev/pr/{PR 番号}/反映作業/index.yaml` を目次の Schema で検査して違反を返す | AI Monitor の検証のコマンドの不具合で、今回の要望に含まれない。このリポジトリでは直せない | 予定なし |
