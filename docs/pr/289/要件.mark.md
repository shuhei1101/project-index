# 要件

## 要望

管理の MCP の `update` が、クローンが既に最新で取り込む commit が無くても、稼働中のプロセスが起動した commit とクローンの HEAD が違えば、依存を入れ直して起動し直すようにする。

<!-- table: {"kind": "data"} -->

| 要件 | 終了の条件 |
| --- | --- |
| 稼働中のプロセスが更新前のコードのときの起動し直し | クローンの HEAD が稼働中のプロセスの起動した commit と違い、上流に新しい commit が無いとき、`update` が `uv sync` と `migrate --plan` を実行し、移し替えが要らなければ `restarting: true` を返して起動し直す |
| 稼働中のプロセスの commit の観測 | 管理の MCP の `status` で、稼働中のプロセスが起動した時点のクローンの commit を返却する。起動し直した後の `status` の値がクローンの HEAD と同じになる |
| 既存の振る舞い | 稼働中のプロセスの起動した commit とクローンの HEAD が同じで、上流に新しい commit も無いときは、今までどおり `updated: false`・`restarting: false` を返して起動し直さない |

<!-- /table -->

応答は `updated` を取り込んだかの意味のまま `false` にし、`restarting: true` で起動し直すことを表す。起動し直す理由は、稼働中のプロセスが起動した commit（`previous_commit`）と取り込んだ後のクローンの HEAD（`commit`）を応答に足して表す（インターフェース定義設計で決定）。
`updated` の意味を変えないため、既存の呼び出し元（反映作業のスクリプト）の判定が変わらない。
