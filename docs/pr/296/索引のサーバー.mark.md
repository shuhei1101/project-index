## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| バリデーション | 1 ファイル 1 文書の `rename` で、正規化した `new_path` が絶対パスか `..` の部分を持つときは、`paths` の照合より先に違反にする | `new_id` から決めた移し先は旧パスと同じフォルダなので対象にならない |
| エラー返却 | `InvalidArgumentError` で、違反の `path` を `operations[{i}].new_path`、文言を本文のファイルの `rename`・`create` の `new_path` と同じにする | 何も書き込まない |
| 共通化 | 配信元の外の判定を `placement.py` から `create` と `rename` の両方で使用する | 切り出す関数の名前と置き場はモジュール構成設計で決める |
| SC-7 | `rename` の異常シナリオに、配信元の外を指す `new_path` を断る分岐を追加する | `minimal_guarantee` の文言は変えない |
| IF-6 | `InvalidArgumentError` の `condition` の配信元の外を指す `new_path` を `create`・`rename` にし、`rename` の `new_path` の異常系のフローに配信元の外を追加する | - |
| MOD-83・MOD-84 | 判定の関数と、`_plan_file_move` の確認の順を記載する | - |
| 既存機能への影響 | 配信元の中を指す `new_path`・`new_id` だけの `rename`・本文のファイルの `rename`・`create` の振る舞いは変えない | 既存の単体・結合テストで回帰を確認する |
