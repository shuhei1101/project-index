# 要件

## 要望

`write_docs` の `create` で、`records` を持たない行の `paths` の先頭から決めた配置先が、行の `paths` のどれにも該当しない（書き込んでも文書にならない）ときは、書き込まずに配置先を決められない違反にする。
配置先が `paths` に該当するときは、今の振る舞いを維持する。

| `paths[0]` | 今の配置先（ID `A`） | `paths` に該当するか | 変更後 |
| --- | --- | --- | --- |
| `docs/*/README.md` | `docs/README.md` | 該当しない | 配置先を決められない違反 |
| `docs/*/*.yaml` | `docs/A.yaml` | 該当しない | 配置先を決められない違反 |
| `docs/**/index.yaml` | `docs/index.yaml` | 該当する | 今のまま（書き込む） |
| `docs/**/*.yaml` | `docs/A.yaml` | 該当する | 今のまま（書き込む） |

- エラーの `message`・違反の `rule`（`{kind} の新しい文書の配置先を決められません`）・`path`（`operations[{i}].kind`）は、既存の配置先を決められない違反と同じにする
- 既存の違反（`records` を持つ行・先頭が glob を含まない・置き換えた後のファイル名に glob が残る・除外の名前に該当する）の条件と修正案は変えない
- 設計書（モジュール構成 MOD-83 の `new_document_path` の `process`・`exceptions`・`unit_tests`、インターフェース定義 IF-6 の `InvalidArgumentError` の `condition`）に、配置先が `paths` に該当しないときの違反を記載する

`未確定`: 配置先が `paths` に該当しないときの修正案（`fix`）（決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | どの型も、Issue の `documents[].paths の先頭のファイル名の glob を * の 1 つだけにしてください` を返却する | 修正案が 1 つで済む | `docs/*/*.yaml` の型はファイル名に既に `*` が 1 つあり、この修正案から修正方法が分からない |
| B | ファイル名に `*` が無い型（`docs/*/README.md`）は A と同じ修正案、ファイル名に `*` がありフォルダの階層の glob が取り除かれる型（`docs/*/*.yaml`）はフォルダの階層の glob を `**` にする旨の修正案を返却する | どちらの型も修正案から修正方法が分かる | 修正案が 1 つ増える |

推奨: B

PR #191 は、修正案から修正方法が分からない不具合を修正したので、同じ不具合を新規に作らない。
