# 要件

## 要望

`write_docs` に、次の 2 つの操作を追加する。
どちらも既存の操作と同じく、配信元ごとの排他ロックの中で全ての変更を当ててからスキーマ・`validators[]`・mdmark の点検に通し、`atomic`・`dry_run`・`expected_version` を既存の操作と同じ意味で受ける。

| 操作 | 終わりの条件 |
| --- | --- |
| 改名 | 1 回の呼び出しで、文書の ID とファイル名を変え、同じ配信元のうち旧 ID か旧パスで文書を指す箇所（`related[].to`・参照の型の値 `{ID}#{項目のパス}`・Markdown の値の `id:{ID}` のリンク・クラス図の `click` の `href`・管理用の YAML の行のパス）が新しい ID かパスを指す。`dry_run: true` で、書き換わる参照元の文書の ID と箇所の一覧を返却し、ファイルを変えない |
| 一括置換 | 1 回の呼び出しで、配信元の文書のうち `filter`（`search_docs` と同じ条件）に該当する文書の、文字列の項目（配列・辞書の配下の文字列を含む）の単語を置き換える。`dry_run: true` で、文書ごとの置換の件数を返却し、ファイルを変えない |

`未確定`: 操作の受け方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `write_docs` の `operations[].op` に `rename`・`replace_text`（仮）を追加する |
| B | `write_docs` とは別のツール（`rename_docs`・`replace_in_docs`）にする |

推奨: A

Issue が `write_docs` の操作として求めており、排他ロック・検査・`atomic`・`dry_run` を既存の操作と共有できるため。一括置換は 1 つの操作で複数の文書に当たるので、`results[]` の返し方を設計で決める。

`未確定`: ID を持つ配信元で、ID を変えずにファイル名だけを変える改名を受けるか（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 新しい ID と新しいパスのどちらか・両方を受け、ファイル名だけの改名も受ける |
| B | 新しい ID だけを受け、パスは `ids.format`・配置先から決める |

推奨: A

ID を持つ設計書は改名しても ID を変えない決まり（knowledge の共通の型 `id` の `x-rules`）で、ファイル名だけを変える改名が要るため。
