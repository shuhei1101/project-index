# 要件

## 要望

`write_docs` に、次の 2 つの操作を追加する。
どちらも既存の操作と同じく、配信元ごとの排他ロックの中で全ての変更を当ててからスキーマ・`validators[]`・mdmark の点検に通し、`atomic`・`dry_run`・`expected_version` を既存の操作と同じ意味で受ける。

| 操作 | 終わりの条件 |
| --- | --- |
| 改名 | 1 回の呼び出しで、文書の ID とファイル名を変え、同じ配信元のうち旧 ID か旧パスで文書を指す箇所（`related[].to`・参照の型の値 `{ID}#{項目のパス}`・Markdown の値の `id:{ID}` のリンク・クラス図の `click` の `href`・管理用の YAML の行のパス）が新しい ID かパスを指す。`dry_run: true` で、書き換わる参照元の文書の ID と箇所の一覧を返却し、ファイルを変えない |
| 一括置換 | 1 回の呼び出しで、配信元の文書のうち `filter`（`search_docs` と同じ条件）に該当する文書の、文字列の項目（配列・辞書の配下の文字列を含む）の単語を置き換える。`dry_run: true` で、文書ごとの置換の件数を返却し、ファイルを変えない |

操作は `write_docs` の `operations[].op` に `rename`・`replace_text` として追加する（インターフェース定義設計で確定）。
`rename` は `new_id`・`new_path` の少なくとも 1 つを受け、ID を変えずにファイル名だけを変える改名も受ける。
