## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 改名の操作 | 対象の文書の ID・パスを変え、同じ配信元の全ての文書から旧 ID・旧パスを指す箇所を探して書き換え、全てを 1 回の検査に通してから書き込む | `write_docs` の `op: rename`（`new_id`・`new_path`） |
| 改名の参照元 | `related[].to`（`source` を持たない行）・スキーマの参照の型（`{ID}#{項目のパス}`）の値・Markdown の値の `id:{ID}` のリンクと `click` の `href`・`records: files` の行のパスの列を対象にする | 探し方はモジュール構成設計で決める。`delete_docs` の `_referrers` と共有できるかを確認する |
| 改名の配置 | `records` の要素の文書（管理用の YAML の行）は、行の `path` と本文のファイルを動かす。1 ファイル 1 文書は YAML のファイルを動かす | 配置先が行の `paths`・`exclude[]` に当たらないときは違反にする |
| 一括置換の操作 | `filter` に該当する文書ごとに、文字列の値を再帰的にたどって単語を置き換え、置き換えた文書だけを検査に通して書き込む | `op: replace_text`（`filter`・`old`・`new`・`fields`）。件数の上限は持たず、書き込みの期限で打ち切る |
| 一括置換の対象の項目 | 既定は文書の全ての項目。項目のパスで絞れるようにする | 共通のキーの列名への読み替えは既存の操作と同じ |
| 書き込みの期限 | 既存の `write_deadline_sec` の中で終える | 件数が多いときの所要時間を結合テストで確認する |
| 既存機能への影響 | `create`・`update`・`replace` と `delete_docs` の入出力は変えない | - |
