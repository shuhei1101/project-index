# 要件

## 要望

読み取り API の文書の取得（`GET /sources/{source}/docs/{path}`）で `ref` を指定したとき、そのリビジョンにだけあり作業ツリーに無い文書を 200 で返却する。

| 項目 | 基準 |
| --- | --- |
| 終了の条件 | `ref` を指定した読み取りで、そのリビジョンにだけある文書が 200 を返却する |
| `updatedAt` | Git の配信元は、指定したリビジョンでファイルを最後に変えた commit の日時（インターフェース定義『文書の取得』の期待値のまま） |
| YAML を読めなかったファイル | `ref` の文書で YAML を読めなかったときも、作業ツリーのファイルを stat せずに `conversionError` つきの 200 を返却する |
| 作業ツリーを参照する場合 | `ref` を省いた読み取りと Git 管理外の配信元の `updatedAt` は今のまま |

調べて分かった原因は次の 2 つで、両方を修正する。

| 原因 | 箇所 |
| --- | --- |
| ファイルの日時を検索する `git log --name-only` はマージ commit の変更ファイルを出さないため、マージ commit で追加したファイルは日時を持たない（`SC-164-54.yaml` は `feat/video/add-script-and-adlib` のマージ commit [d9b512b6](https://github.com/shuhei1101/aituber/commit/d9b512b6) で両方の親に対して追加されている） | `src/project_index/features/history/query.py` の `file_dates` |
| 日時を持たない文書は、`ref` を指定しても作業ツリー（`source.root`）のファイルを stat する | `src/project_index/features/read/service.py` の `get_document`（通常の文書と YAML を読めなかったファイルの 2 か所） |

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| `features/read/service.py` の `get_document` の `updated_at` | [c19c617](https://github.com/shuhei1101/project-index/commit/c19c617)（`dev-docs の文書の MCP・管理の MCP・配信元の読み込みとプラグインを移し、画面のサーバー向けの読み取り API と端末の設定の API を提供する (#15)`） | 読み取り API を新設したときに、Git 管理外の配信元の更新日時をファイルの更新日時で取るために配置した。`ref` を指定した読み取りで日時が欠けることは想定していない | 1 回 | `ref` のある読み取りの場所で作業ツリーを stat しないように分けても、Git 管理外の配信元の目的は壊さない |
| `features/history/query.py` の `file_dates` | [c19c617](https://github.com/shuhei1101/project-index/commit/c19c617)（同上） | ファイルごとの最初と最後の commit の日時を 1 回の git で検索するために配置した。マージ commit で追加したファイルの扱いは決めていない | 1 回 | マージ commit の変更ファイルも数えると、検索の `updated`・`created` の値もマージ commit の日時になりうる |
