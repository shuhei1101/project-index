# 要件

## 要望

配信元の設定 `project-index.yaml` に `direct_commit` を追加し、dev-docs の画面から develop へ直コミットしてよい種類を `kinds` に並べる。
許可した種類を、端末の設定の project-index の行の `sources[].direct_commit.write_api_kinds` に登録する（反映作業）。

<!-- table: {"kind": "data"} -->

| 要件 | 終了の条件 |
| --- | --- |
| 配信元の設定の直コミットの許可 | `project-index.yaml` が `direct_commit.branch: develop` と `direct_commit.kinds` を持ち、管理の MCP の `check_project` が違反を返さない |
| 管理用の YAML の種類の本文の保護 | `records: files`・`body_file: path` の行の種類は、`kinds` に `body: false` の行として並ぶ |
| 画面の書き込みの API からの許可 | マージの後、端末の設定の API（`GET /settings/sources`）の project-index の行の `directCommit.writeApiKinds` が `kinds` の全ての種類を持つ |

<!-- /table -->

`kinds` に並べる種類は次のとおり（ドキュメント修正で決定）。

<!-- table: {"kind": "data"} -->

| 種類 | 許可 | 理由 |
| --- | --- | --- |
| YAML の設計書（`architecture`・`nonfunctional`・`scenario`・`interface`・`module`・`config`・`api`・`library`・`test_procedure`・`dev_command`・`layout`・`agent`・`mcp_server`・`launch`・`agent_flow`・`llm_call`・`evaluation`・`eval_criterion`・`eval_case`）・用語集（`glossary`）・目次（`index`） | 本文ごと許可 | スキーマで検査してから書き込むため。shuhei1101/dev-docs#317 と同じ |
| 管理用の YAML（`files_guide`・`src`・`tests`・`plugin`・`docs_folder`・`repo`・`root`） | `body: false` | 本文はコード・Markdown で、メタデータだけを画面から直す |
| プロンプト（`prompts`） | 許可しない | 稼働中のサーバーが読む本文そのもので、画面から develop へ直接入れない |

<!-- /table -->

規約『ユーザー確認が必須な事項』の論点の型には当たらないと判定した。
許可は画面から直コミットできる種類を決めるだけで、公開リポジトリへ入る変更は、利用者が画面で行う書き込みの 1 回ごとに利用者自身が決める。
費用・権限・要件の変更・戻せない変更も伴わない（設定から行を消せば許可を取り下げられる）。
