# 要件

## 要望

配信元の設定 `project-index.yaml` に `direct_commit` を追加し、dev-docs の画面から develop へ直コミットしてよい種類を `kinds` に並べる。
許可した種類を、端末の設定の project-index の行の `sources[].direct_commit.write_api_kinds` に登録する（反映作業）。

<!-- table: {"kind": "data"} -->

| 要件 | 終了の条件 |
| --- | --- |
| 配信元の設定の直コミットの許可 | `project-index.yaml` が `direct_commit.branch: develop` と `direct_commit.kinds` を持ち、管理の MCP の `check_project` が違反を返さない |
| 管理用の YAML の種類の本文の保護 | `records: files`・`body_file: path` の行の種類は、`kinds` に `body: false` の行として並ぶ |
| 画面の書き込みの API からの許可 | マージの後、端末の設定の API（`GET /settings/sources`）の project-index の行の `directCommit.writeApiKinds` が `kinds` の全ての種類を持つ |

<!-- /table -->

`未確定`: `kinds` に並べる種類（決める段: ドキュメント修正。規約『ユーザー確認が必須な事項』に当たるかもこの段で判定する）

| 案 | 内容 |
| --- | --- |
| A | YAML の設計書の種類（`architecture`・`nonfunctional`・`scenario`・`interface`・`module`・`config`・`api`・`library`・`test_procedure`・`dev_command`・`layout`・`glossary`・`index`・`agent`・`mcp_server`・`launch`・`agent_flow`・`llm_call`・`evaluation`・`eval_criterion`・`eval_case`）を許可し、管理用の YAML の種類（`files_guide`・`src`・`tests`・`plugin`・`docs_folder`・`repo`・`root`）を `body: false` で許可する。変換で配信するプロンプト（`prompts`）は許可しない |
| B | 管理用の YAML の種類だけを `body: false` で許可する |

推奨: A

shuhei1101/dev-docs#317 と同じ考え方で、スキーマで検査できる YAML の文書は本文ごと、コードの本文を持つ種類はメタデータだけを画面から直せるため。
プロンプトは稼働中のサーバーが読む本文そのもので、画面から develop へ直接入れない。
