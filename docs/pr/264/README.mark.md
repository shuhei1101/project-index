# 画面からの直コミットが衝突したときに、修正をブランチに残して端末のスクリプトを実行し、項目ごとのバージョンを返却する

## 概要

画面からの直コミットがほかの変更と衝突しても、利用者の修正がブランチに残り、端末に配置したスクリプトで後の処理（プッシュ・PR の作成など）を AI に任せられるようになる。
画面は項目ごとのバージョンで照合でき、同じ文書の別の項目の変更とは衝突しなくなる。

## 背景

[Issue #263](https://github.com/shuhei1101/project-index/issues/263) の要望。
画面のサーバーからの直コミット（[画面のサーバーからの直コミットの書き込み](../../interface/IF-38.yaml)）は、文書のバージョンが取り込んだ後の今のバージョンと合わないと 409（`VersionMismatchError`）で断り、利用者は今の内容を読み込み直して手でもう一度修正している。
照合は項目ごとのハッシュ（`expected_version` の辞書）でもできるが、項目ごとのハッシュを返却する読み取り API が無く、画面は文書の全体でしか照合できない。

衝突したときだけ project-index がブランチを作成して修正をコミットし、その後の処理は端末の設定で指定したスクリプトに任せる（Issue の「決まったこと」）。
後続は画面の側の [shuhei1101/dev-docs#314](https://github.com/shuhei1101/dev-docs/issues/314)。
