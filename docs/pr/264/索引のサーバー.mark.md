## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 書き込みの API の要求 | 編集を始めたときのコミットの SHA を省略できるキーで受け取る | 省いた要求は今と同じに断る |
| 衝突の判定 | 今のブランチで断られ、編集を始めたときのコミットでは許可と検査に合格する要求を衝突にする | 要件 9 |
| ブランチへのコミット | 起点のコミットから一時のワークツリーでブランチを作成し、要求の全ての書き込みと削除を 1 つのコミットにする。コミットの後に一時のワークツリーを削除し、ブランチだけを残す | ブランチの名前の付け方はインターフェース定義設計で決める |
| スクリプトの実行 | 端末の設定で指定したスクリプトに、配信元・ブランチ・コミットを指定して制限時間つきで実行し、終了コードと出力を応答に入れる | 指定が無ければ実行しない |
| 応答 | 衝突したときは 409 でなく、ブランチ・コミット・スクリプトの結果を返却する | ステータスコードはインターフェース定義設計で決める |
| 端末の設定 | スクリプトの指定のキーを配信元の行に追加し、端末の設定の API では受け付けない | 要件 10 |
| 文書の取得 | 項目のパスごとの `value_hash` を返却する | 返却する項目の深さはインターフェース定義設計で決める |
| 権限・認可 | スクリプトの指定は端末の設定のファイルだけから参照し、配信元の設定と HTTP の要求からは指定させない | 任意のコマンドの実行を防ぐ |
| 既存機能への影響 | 衝突しない要求と `write_docs`・`delete_docs` の `commit` の振る舞いは変えない | - |
| 性能 | スクリプトの制限時間を非機能要件の決定値として持つ | 書き込みの期限との関係も決める |
