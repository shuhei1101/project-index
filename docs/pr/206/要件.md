# 要件

## 要望

`docs/guide/メタデータを付ける基準.md` を次のとおりに書き換える。

- 判定で決定する基準を、`documentsの行の判定.md` と同じ構成（`## 判定フローチャート` の mdmark の map の中の mermaid の `flowchart TD`、`Q{番号}` の質問のノードと `YES` / `NO` の分岐、`※{番号}` の注記）の判定フローチャートにする。対象は次の 2 つ
  - 仮のメタデータを付けるときに、どの段階まで参照するか（目次のページの有無・`outline` の `next_stage`・見出しの直下の段落・コードブロック以外の文章・全文）
  - 関連の候補を付けるときに、どの行にどの `type`（`tests`・`implements`・`see_also`）を付けるか（`links` の出力の指す側・指される側を含む）
- 判定で決定しない基準（`name`・`description`・`tags` の記載方法、`skew`・`changed` のコマンドと出力の扱い）は、判定フローチャートの注記か箇条書きに残す。基準の中身は変えない
- エイリアスを付ける基準のセクションを追加する。決める内容は次の 3 つ
  - どの文書に付けるか（`alias_type` を持つ `documents` の行の文書か。管理用の YAML の行は `files[].id` を持たせて照合させるか）
  - いつ付けるか（行を追加したとき・本文や会話で `name` と違う呼び名が使用されたとき）
  - `aliases` にどの単語を入れるか（本文や会話で文書を指す別の呼び名。エイリアスのキーは alias-inject のスキーマに従う）
- 既存の見出し `## 仮のメタデータ`・`## メタデータの偏りの見直し`・`## 中身が変わったファイルの見直し`・`## 関連の候補` は保つ（`配信元を登録する.md` と [エージェントが調べる](https://github.com/shuhei1101/project-index/blob/1ad0764/docs/scenario/SC-6.yaml) がセクションの名前で取得するため）

`配信元を登録する.md` の手順 4 の、基準のセクションを指す行に、エイリアスを付ける基準のセクションを加える。
