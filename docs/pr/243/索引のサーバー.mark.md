## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 生成のコマンド | `src/project_index/features/` に機能のフォルダを新規作成し、`project-index` のサブコマンドとして登録する。配信元の直下で動き、`docs/agent-flow/*.yaml` の全てを読み込んでスキーマで検査し、`type: skill` の文書ごとに SKILL.md を組み立て、中身が違うものだけを書き出す | 入出力は IF-37『SKILL.md の生成』（`project-index skill-md`） |
| 引数 | `generators[].run` が後ろに付与する書き込んだ文書のパスは受け取るが、生成の対象は絞らず全ての `type: skill` を組み立てる | `ref` の工程の埋め込みで、ほかの文書の書き込みが別の SKILL.md に影響するため |
| 失敗 | 読み込めない・スキーマに合わない・`ref` が解決できない・`skill.path` が配信元の外部を指すときは、どの SKILL.md も書き換えずに終了コード 0 以外で終え、標準エラーに文書のパスと項目を出す | `write_docs`・`delete_docs` は生成の失敗をサーバーのログに残すだけで、書き込みの結果を変えない（既存の振る舞い。[IF-6](https://github.com/shuhei1101/project-index/blob/e0bbd7b/docs/interface/IF-6.yaml) の制約「書き込み後の生成の制限時間」）。書き込みで起きうる失敗は「書き込み前の検査」で止める |
| 書き込み前の検査 | 同じコマンドに検査のモードを持たせ、`validators[]`（`on: [write]`）に登録して `agent_flow` の行の `validators[]` で指す。標準入力の書き込む文書で配信元の同じ ID の文書を置き換えた上で全ての `type: skill` を組み立て、`ref` が解決できない・`skill.path` が配信元の外部を指すときは違反を返却する | 書き込みは `ValidationFailedError`（`atomic: false` は `failed`）で断られ、エージェントフローも SKILL.md も書き換わらない。`delete_docs` は検査を実行しないため、`ref` の参照先の削除はスコープ外 |
| スキーマ | `project-index.yaml` の `agent_flow` の行の `schema`（knowledge の `design-schemas/v9.2.0` の `agent_flow.schema.yaml`）で検査する | - |
| generators・validators への登録 | `project-index.yaml` に `generators[]` と `validators[]` の行を追加し、`agent_flow` の文書の行の `after_write[]`・`validators[]` で指す | - |
| 処理時間 | `script_timeout_sec` の中で終わる | [非機能要件](https://github.com/shuhei1101/project-index/blob/bce129e/docs/nonfunctional/NFR-1.yaml) のスクリプトの制限時間 |
