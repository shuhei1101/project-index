### #60

`PUT`・`POST /settings/sources` の本文に `expectedVersion` が無いときは、端末の設定を読まずに 400 で断る。
送信したときの照合（違えば 409 で `current` を返す）は今のまま。

### #83

`records`・`body_file` の行の文書で、`write_docs`・`delete_docs` が本文のファイルを次のとおり扱う。

| 操作 | 入力 | 結果 |
| --- | --- | --- |
| `op: create` | `data` に要素のキーと本文、`body_file` の列に本文のファイルのパス | 要素を追加し、本文のファイルを作成する |
| `op: update` の `set` | 本文全体 | 本文のファイルを置き換える |
| `op: update` の `text_edits` | 本文・`old`・`new`・`replace_all` | 本文のファイルの一部だけを置き換える。`old` が無い・複数ある（`replace_all` なし）ときは書き込まずにエラーを返却する |
| 版の照合 | `expected_version` | 要素と本文の両方を含めた版で照合する |
| `dry_run` | `true` | `diff` に本文のファイルの差分を含めて返却し、書き込まない |
| `delete_docs` | 文書の ID | 要素と一緒に本文のファイルも削除する |

本文のファイルを書き込めない（パスが配信元の外を指す）ときは、要素も書き込まずにエラーを返却する。`scope.write` は作業場所（`cwd`）と比べるもので、`scope.write` に当たらない作業場所からの書き込みは今の書き込みと同じく断る。
特定の配信元に寄せない。

本文は、種類の列名と重ならない `@body`（`data`・`set` のキーと `text_edits[].field`）で受ける（[#83 の確認](https://github.com/shuhei1101/project-index/issues/83#issuecomment-6895617805) の案 A）。`body_file` の列の名前が `body` の配信元でも、`body` は列を指す。
