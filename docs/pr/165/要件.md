# 要件

## 要望

`write_docs` の `rename`・`replace_text` を、`records`・`body_file` の行の文書の本文のファイルにも適用する。
本文のファイルの書き換えは、既存の操作と同じく配信元ごとの排他ロックの中で YAML の項目の書き換えと一緒に検査し、`atomic`・`dry_run`・`expected_version` を同じ意味で受ける。

| 操作 | 終わりの条件 |
| --- | --- |
| 改名 | 1 回の呼び出しで、同じ配信元の `records`・`body_file` の行の文書の本文のファイルのうち、旧 ID を指す `id:{旧 ID}` のリンクと、本文のファイルのフォルダから解くと改名前のパスになる Markdown のリンクの先が、新しい ID・パスを指す。`dry_run: true` で、書き換わる本文のファイルの箇所を YAML の項目の箇所と同じ一覧で返却し、ファイルを変えない |
| 一括置換 | 1 回の呼び出しで、`filter` に該当する `records`・`body_file` の行の文書の本文のファイルの `old` を `new` にする。`fields` で本文のファイルを対象に含めるか外すかを指定できる。`dry_run: true` で、文書ごとの置換の件数に本文のファイルの件数を含め、ファイルを変えない |

`未確定`: 本文のファイルの中で書き換える参照の範囲（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `id:{旧 ID}` のリンク（直後が `#`・`)`・`"`・`'`・空白・末尾）と、Markdown のリンクの先の相対パスだけを書き換える（YAML の項目の (3)(4) と同じ規則）。値の全体が旧パスになる行は本文のファイルには無いため扱わない |
| B | A に加え、本文中の地の文の旧 ID（`IF-6` のような単語）も書き換える |

推奨: A

YAML の項目と同じ規則にそろえると、書き換わる箇所が利用者に予測でき、地の文の単語は `replace_text` で明示して置換できるため。

`未確定`: 一括置換で本文のファイルを対象にする既定（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `fields` を省いたときは本文のファイルも対象にし、`fields` に `@body` を含めたときだけ本文のファイルを対象にする |
| B | `fields` に `@body` を含めたときだけ本文のファイルを対象にし、省いたときは今までどおり YAML の項目だけ |

推奨: A

`fields` を省いた既定は「文書の全ての項目」と定めており、本文のファイルは `@body` として文書の一部に当たるため。`@body` は `text_edits` と同じ名前で指せる。
