# 要件

## 要望

| 番号 | 終わりの条件 |
| --- | --- |
| 1 | 配信元の登録・見直しの手順と、メタデータ（`name`・`description`・`tags`・関連）・エイリアスを付ける基準が、配信元 `project-index` の `docs/guide/` のページにある。SKILL.md の本文の手順と基準はそのページへ移し、SKILL.md には手順のページの取得と、質問・確認の進め方だけを残す |
| 2 | 端末の設定の `sources[]` に配信元 `project-index` の行が無い端末（`sources: []` を含む）で、文書の MCP から 1 の手順のページを取得できる |
| 3 | スキル `setup` を起動していないエージェントが、作業の途中で 1 の基準のうち必要な箇所（例: 仮のメタデータの付け方）だけを取得できる |
| 4 | スキル `setup` は 1 の手順を文書の MCP で取得して進める。スキルの呼び方と引数（`[path]`）は変えない |
| 5 | 1〜3 の取得は knowledge の配信元を要しない。knowledge の同じ種類の文書は、配信元が使えるときだけ参照する |
| 6 | 手順と基準の文言を変えたときに、プラグインの更新を要さず、クローンの更新（管理の MCP の `update`）で取得する内容が変わる |

- 確認方法: `sources: []` の端末の設定で `project-index serve` を起動し、文書の MCP で手順のページの全文と、基準の 1 つの箇所を取得できることを観測する。配信元 `project-index` を登録した端末でも、同じ内容を取得できることを観測する
- 基準は SKILL.md の中身を変えずに移す。エイリアスに関わる記述は、alias-inject の設定との紐づけとして手順のページの手順 6 に残す。基準を判定フローチャート・判定表の形に整理し、エイリアスを付ける基準を加えることはスコープ外にする（#203）
- 配信元が登録されていない端末で手順のページを返す経路は、クローンの `project-index.yaml` のうち `docs/guide/` の行を、端末の設定に配信元 `project-index` の行が無いときだけ組み込みの配信元 `project-index` として配信し、作業範囲の外（参考）として `search_docs`（`outside_scope: true`）で返却する形にする。書き込みは受け付けない。要望 3 の一部のセクションの取得と #199 の通知からの参照を、文書の ID とセクションで指す `search_docs` の既存の引数で満たせ、`describe` の引数・MCP のプロンプトで返す形は同じ取得の機構を別に作ることになるため
