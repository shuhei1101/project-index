# 要件

## 要望

| 番号 | 終わりの条件 |
| --- | --- |
| 1 | 配信元の登録・見直しの手順と、メタデータ（`name`・`description`・`tags`・関連）・エイリアスを付ける基準が、配信元 `project-index` の `docs/guide/` のページにある。SKILL.md の本文の手順と基準はそのページへ移し、SKILL.md には手順のページの取得と、質問・確認の進め方だけを残す |
| 2 | 端末の設定の `sources[]` に配信元 `project-index` の行が無い端末（`sources: []` を含む）で、文書の MCP から 1 の手順のページを取得できる |
| 3 | スキル `setup` を起動していないエージェントが、作業の途中で 1 の基準のうち必要な箇所（例: 仮のメタデータの付け方）だけを取得できる |
| 4 | スキル `setup` は 1 の手順を文書の MCP で取得して進める。スキルの呼び方と引数（`[path]`）は変えない |
| 5 | 1〜3 の取得は knowledge の配信元を要しない。knowledge の同じ種類の文書は、配信元が使えるときだけ参照する |
| 6 | 手順と基準の文言を変えたときに、プラグインの更新を要さず、クローンの更新（管理の MCP の `update`）で取得する内容が変わる |

- 確認方法: `sources: []` の端末の設定で `project-index serve` を起動し、文書の MCP で手順のページの全文と、基準の 1 つの箇所を取得できることを観測する。配信元 `project-index` を登録した端末でも、同じ内容を取得できることを観測する
- 判定フローチャート・判定表の形にする基準は、`docs/guide/` の既存の判定フローチャート（[新しく作るか修正するかの判定](../../guide/新しく作るか修正するかの判定.md)・[documentsの行の判定](../../guide/documentsの行の判定.md)）と同じ形にする

`未確定`: 配信元が登録されていない端末で手順のページを返す経路（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | クローンの `project-index.yaml` のうち `docs/guide/` の行を、端末の設定に行が無くても組み込みの配信元として配信し、作業範囲の外（参考）として `search_docs`（`outside_scope: true`）で読めるようにする | 既存の `search_docs`・`trace_related` の引数で、ページの全文・節（`sections`）・関連をそのまま取得できる。#199 の通知から文書の ID と節で指せる | 引数なしの `describe` の一覧に、登録していない配信元が出る。組み込みの配信元の書き込みの権限を決める必要がある |
| B | `describe` に手順を返す引数を追加し、クローンの `docs/guide/` のページを返す | 配信の対象を増やさない | 節だけの取得・関連のたどりを `describe` に作り直すことになり、`search_docs` と同じ問いに答える機構が 2 つになる |
| C | MCP のプロンプトかリソースとして返す | 配信元の一覧に影響しない | スキル・エージェントからの呼び出し方が文書の MCP のツールと別になり、節だけの取得ができない |

推奨: A

要望 3 の節だけの取得と #199 の通知からの参照は、文書の ID と節で指す `search_docs` の既存の引数で満たせる。B・C は同じ取得の機構を別に作ることになる。
