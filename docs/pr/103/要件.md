# 要件

## 要望

起動の後に `GET /sources` が、全ての配信元の読み込みを待たずに応答する。
#85 と同じ条件（状態のフォルダを空にして起動し、WSL の `/mnt/c` の下の配信元 14 件を配信）で、待ち受けを始めてから `GET /sources` が 2 秒以内に応答するまでの時間を、待ち受けまでの時間と同じ桁（10 秒以内）にする。

`GET /sources` は全ての行の読み込みを待たず、読み込みが終わっていない配信元を読み込み中として端末の設定の順に並べて返す。
応答の値の形（状態の値の名前・dev-docs の画面のサーバーとの互換）はインターフェース定義設計で決める。

起動の後の全ての行の読み込みは、行を並列に読み込んで短くし、読み込みの遅い行がほかの行の読み込みを止めないようにする。
同時に読み込む行の数は、モジュール構成設計で規約『資源の値の決め方』に沿って導く。
並列に読み込むだけでは、配信元の数と `/mnt/c` の読み込みの速さに `GET /sources` の応答の時間が左右され、10 秒以内を満たせる保証が無いため、`GET /sources` が待たないことと両方を行う。
ext4 の端末の配信元 15 件で、develop の待ち受けから `GET /sources` の応答まで 14.5 秒（待ち受けまで 2.3 秒・応答まで 16.8 秒）かかり、`/mnt/c` の #85 の計測（506.7 秒）とともに、応答の時間が行の読み込みの時間で決まっている。
