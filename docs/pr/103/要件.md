# 要件

## 要望

起動の後に `GET /sources` が、全ての配信元の読み込みを待たずに応答する。
#85 と同じ条件（状態のフォルダを空にして起動し、WSL の `/mnt/c` の下の配信元 14 件を配信）で、待ち受けを始めてから `GET /sources` が 2 秒以内に応答するまでの時間を、待ち受けまでの時間と同じ桁（10 秒以内）にする。

`未確定`: 読み込みが終わっていない配信元を `GET /sources` でどう返すか（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 読み込みが終わっていない配信元を新しい状態（`loading`）で返し、`GET /sources` は読み込みを待たない |
| B | 応答の形は変えず、行の読み込みを並列にして全ての行の読み込みを短くし、`GET /sources` は今どおり全ての行を待つ |

推奨: A

B は配信元の数と `/mnt/c` の読み込みの速さに応答の時間が左右され、10 秒以内を満たせる保証が無い。A は読み込みの時間によらず応答し、応答の形の変更は dev-docs の画面のサーバーへの追加の値 1 つに留まる。
