## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 書き込みの検査のスキーマ | worktree を指した呼び出しで `schema.ref` の行のスキーマを、worktree の設定で作り直した配信元が解いたスキーマにする。起動時のスキーマのキャッシュは、配信中の配信元と worktree の配信元を区別するキーにする | `default_ref`・`ref` の呼び出しは今までどおり |
| 読み取りのメタデータ | worktree の文書のキャッシュの照合に行の定義を加え、`metadata` を変えた行の文書を、変えた後の対応で読み込み直す | 変わらない行の文書は読み込み直さない |
| 読み取りの参照先 | `search_docs`・`trace_related` が worktree を指したとき、worktree の設定で作り直した配信元で参照するかを確認し、作り直していない経路があれば作り直す | 確認の結果: どちらも `resolve_read_targets` の既定（`reload_worktree: true`）で `load_source_at` を通り、作り直した配信元で参照する。原因は文書のキャッシュのキーが行の定義を含まないこと（[要件](./要件.md) の `## 変更箇所の由来`） |
| 既存機能への影響 | `delete_docs`・`list_changes`・`list_match_words` など同じ文書のストアを参照するツールも、worktree を指したときは同じく worktree の行で参照する | 入出力の構造は変えない |
