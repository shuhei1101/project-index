### #136 同じファイルの重なりの検出

- 有効な 2 つ以上の documents の行が同じファイルを文書にするとき、`check_sync` の結果にファイルと行の ID の組を 1 件ずつ入れる
- `check_project` の索引の同期に件数と内訳を出し、起動時の検査（`log_source_check`）が警告のログに記載する。`status` の同期の件数と引数なしの `describe` の警告も、既存の 4 種類と同じく重なりを含める
- 重なりの無い配信元では件数が 0 で、既存の検出の結果は変わらない
- 行が文書にするファイルは、`records` を持たない行ではヒットしたファイル、`records`・`body_file` の行では要素の `body_file` が指すファイルとする。`records` の行の管理用の YAML 自体は数えない（管理用の YAML を目次の種類の文書として別の行で配信する配置を重なりにしないため）

### #138 x-key の値での要素の指定

- `write_docs` の `text_edits` の `field` に、`#` で始まる参照の型の項目のパス（`#functions[apply_migration].process`）を受け付ける。書き方は設計書の参照の型（`{ID}#{項目のパス}`）の `#` から後と同じで、配列の要素を種類のスキーマの `x-key` の値で指す
- 指した要素の中の文字列の項目の一部を置き換える
- `#` で始まらない既存の `[n]`・`[]`・`[{キー}]`（キーが真の要素）の意味と、それを使用する `metadata` の列名・`search_docs`・`list_changes` の結果は変えない
- `x-key` を持たない配列・該当する要素が無い値・無い順番・無いキーは `text_edits[{n}].field` の違反として返却する
