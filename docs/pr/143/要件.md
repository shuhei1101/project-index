### #136 同じファイルの重なりの検出

- 有効な 2 つ以上の documents の行が同じファイルを文書にするとき、`check_sync` の結果にファイルと行の ID の組を 1 件ずつ入れる
- `check_project` の索引の同期に件数と内訳を出し、起動時の検査（`log_source_check`）が警告のログに記載する
- 重なりの無い配信元では件数が 0 で、既存の検出の結果は変わらない

`未確定`: 行が文書にするファイルの範囲（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `paths` の行はヒットしたファイル、`records`・`body_file` の行は要素の `body_file` が指すファイルを、その行が文書にするファイルとする |
| B | A に加えて、`records` の行の管理用の YAML 自体も、その行が文書にするファイルとする |

推奨: A

#136 の例（管理用の YAML の行のファイルと YAML の文書の行の `paths` が同じファイルを指す）は A で検出でき、管理用の YAML を目次の種類の文書として別の行で配信する今の配置を重なりにしないため。

### #138 x-key の値での要素の指定

- 位置を調べずに、種類のスキーマで配列の要素が持つ `x-key` の値で要素を 1 つ指す項目のパスの書き方を新設する
- `write_docs` の `text_edits` の `field` がその書き方を受け付け、指した要素の中の文字列の項目の一部を置き換える
- 既存の `[n]`・`[]`・`[{キー}]`（キーが真の要素）の意味と、それを使う `metadata` の列名・`search_docs`・`list_changes` の結果は変えない
- `x-key` を持たない配列・該当する要素が無い値・2 つ以上に該当する値は違反として返却する

`未確定`: 書き方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `functions[name=apply_migration].process` のように、`[{x-key のキー}={値}]` で記載する |
| B | `functions[=apply_migration].process` のように、`[={値}]` で記載し、キーはスキーマの `x-key` から参照する |

推奨: A

パスだけでどのキーで選んだかが分かり、`[{キー}]` と `=` の有無で見分けられるため。
