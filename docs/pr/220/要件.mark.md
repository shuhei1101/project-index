# 要件

## 要望

| 番号 | 終わりの条件 |
| --- | --- |
| 1 | `records`・`body_file` の行で、`create` の `data` の `body_file` の列が配信元の中の既にあるファイルを指し、`@body` が無いとき、そのファイルを本文のファイルとする要素を作成できる。本文のファイルの中身は変えない |
| 2 | 本文のファイルを持たない要素への `update`・`replace` で、`body_file` の列に既にあるファイルを指定し `@body` を指定しないときも、要望 1 と同じくそのファイルを本文のファイルとして付けられる |
| 3 | `body_file` の列も `@body` も指定した `create` の断りのエラーの直し方が、取れる方法（既にあるファイルを使うなら `@body` を除く・本文を書くなら新しいファイルのパスにする）を示す |
| 4 | `body_file` の列だけを指定し、指すファイルが無いときのエラーの直し方が、取れる方法（`@body` を加える・先に本文のファイルを作成する）を示す |

- 既にあるファイルが、ほかの文書の本文のファイルになっている（同じ管理用の YAML のほかの要素が指している）ときは、今どおり `body_file` の列の違反で断る。1 つの本文のファイルを 2 つの文書で持つと、`rename`・`delete_docs` で本文のファイルを移す・消すときにもう片方が壊れるため
- `@body` を指定し、既にあるファイルを指す `create` は、今どおり断る（既にあるファイルを上書きしない）
- 既にあるファイルを本文のファイルにした要素の `version`・`diff` は、本文のファイルを書いたときと同じく要素と本文のファイルから求め、`diff` に本文のファイルの差分の行は並べない
- 確認方法: Issue の手順（本文のファイルを先に作成し、`data.body` にそのパスを指定した `create`）を `dry_run: true` で流し、検査に通ることを観測する
