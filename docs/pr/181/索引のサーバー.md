## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 読み取りの結果のキャッシュのキー | 今のキーに、validators の行の定義のハッシュ・スクリプトの内容を表す値・参照する場所（クローン本体か worktree か）を加える | モジュール構成設計の結果: `DocumentChecker._read_key` で、行の全ての項目の『値のハッシュ』・スクリプトの状態・`target.worktree` の絶対パス（クローン本体は空）を今のキーに加える |
| スクリプトの内容 | worktree では作業ツリーのスクリプトのファイルの内容、クローン本体ではスクリプトを取り出す commit（`config_commit`）をキーに含め、commit していない書き換えでも次の呼び出しから検査し直す | モジュール構成設計の結果: 内容を参照せず、`run` が指すファイルのフォルダの配下（`__pycache__` を除く。Git の配信元では Git が管理・無視していないファイルだけ）のファイルの `stat`（相対パス・`st_mtime_ns`・`st_size`）で表す。スクリプトの実行がフォルダをサブフォルダごと取り出すため、配下の import 先の書き換えも検出する。1 回の `search_docs` の中では、同じスクリプトの状態を 1 回だけ作って文書の間で使い回す。測った値: knowledge の develop の worktree の `scripts/`（Git の無視する `node_modules/` を含め 16,541 ファイル）で、Git の対象の 25 ファイルの走査は 1 回 8.3 ミリ秒（全てを走査すると 0.56 秒）。読み取りの上限（#82）の内に収まる |
| 書き込みの検査 | 今までどおりキャッシュしない | - |
| 既存機能への影響 | 入出力の構造は変えない。`reload` で全てのキャッシュを捨てる振る舞い（`clear`）は保つ | - |
