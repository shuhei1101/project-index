# 検査の読み取りの結果のキャッシュのキーに validators の行の定義・スクリプトの内容・参照する場所を含め、変わる前の結果を返却しないようにする

## 概要

エージェントが worktree の `project-index.yaml` で validators の行を変えたり検査のスクリプトを書き換えたりしたとき、その worktree を指した読み取りが、変えた後の行とスクリプトで検査した結果を返却するようにする。

## 背景

[Issue #178](https://github.com/shuhei1101/project-index/issues/178) の不具合。
検査の読み取りの結果のキャッシュ（`DocumentChecker._read_cache`）のキーが (配信元の ID, 種類, 検査の ID, 文書のバージョン) で、validators の行の定義・スクリプトの内容・読む場所を含まない。
そのため、文書が変わらない限り、`on: read` の検査は変わる前の結果を返却する。

作業 PR [#176](https://github.com/shuhei1101/project-index/pull/176)（起点 Issue [#175](https://github.com/shuhei1101/project-index/issues/175)）で、文書のストアのキャッシュのキーに文書の行の定義のハッシュを加えた。
その調査で同じ型の欠けが検査の読み取りの結果のキャッシュにもあると分かり、#176 のスコープ外として切り出した。
