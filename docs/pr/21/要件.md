### #6 配信元の設定の paths[] の基準のフォルダ

- 配信元の設定に、`paths[]` の基準のフォルダを指定するキーを追加する。基準のフォルダは、設定ファイルのフォルダか、それより上のフォルダを指定できる
- キーを省いた設定は、今と同じく設定ファイルのフォルダを基準に解く
- 基準のフォルダの外（`..`）を指す `paths[]` は、今と同じく違反にする
- 起動・読み直し・`check_project` で同じ解き方をする
- Git の配信元で、`paths_base` がリポジトリの直下より上を指すときは違反にする（`default_ref` の commit からはリポジトリの外を読めない）
- キー名は `paths_base`。設定ファイルのフォルダからの相対パスで書く
- `paths_base` で変わるのは `paths[]` の解き方と、返却する文書のパスの基準だけにする。`schema` などのほかの相対パス・`scope.write` の既定・作業中の配信元の判定は、今どおり設定ファイルのフォルダで解く

配信元のフォルダごと置き換えると、基準のフォルダをリポジトリの直下にした配信元がリポジトリの直下の配信元と同じ深さになり、作業中の配信元が決まらなくなる。`scope.write` の既定もリポジトリ全体に広がり、TH-407 の「設計書やコードまで参照できてしまう」懸念に戻る。

### #11 端末の設定の最上位の知らないキー

- 端末の設定の最上位に知らないキーがあっても、起動・読み直し・設定の画面の取得・保存・1 行の追加・`project-index migrate` を続ける
- 保存・1 行の追加・`project-index migrate` では、知らないキーをファイルに残す
- 知らないキーは、キーのパスつきの警告として返す
- `sources[]` の行と `scope` の知らないキーは、今どおり違反にする
- 警告は、起動・読み直しの警告のログ、引数なしの `describe` の `warnings[]`、端末の設定の API（取得・保存・1 行の追加）の応答の `warnings[]` で返却する。管理の MCP の `status`・`reload` の結果には記載しない
