# 配信元の設定の paths[] の基準のフォルダの指定と、端末の設定の最上位の知らないキーの警告を追加する

## 概要

利用者が、配信元の設定ファイルをノードのフォルダに置いたまま、その上のフォルダにある文書を選んで配信できるようになる。
あわせて、端末の設定の最上位に project-index の知らないキーがあっても、サーバーが読み込みを続け、知らないキーをパスつきの警告として返すようになる。

## 背景

[Issue #20](https://github.com/shuhei1101/project-index/issues/20) は、同じ種類（`kind:機能の追加`）で対象が重なる 2 件を束ねた Issue。

- [#6](https://github.com/shuhei1101/project-index/issues/6): 配信元の設定の `paths[]` は設定ファイルのフォルダを基準に解き、`..` で外を指すと断る。aituber はノードごとの配信元の設定をノードのフォルダ（`content/node-docs/brain/`）に置くため、共有の `content/node-docs/shared/` やリポジトリの `docs/` を指定できない（D-189 で基準のフォルダを指定するキーの追加に決めた）
- [#11](https://github.com/shuhei1101/project-index/issues/11): 端末の設定のスキーマと型は最上位に知らないキーがあると違反にし、起動・設定の画面の取得と保存・読み直しが失敗する。MindStella が同じ端末の設定のファイルに自分のキーを持てるよう、最上位の知らないキーは警告にする（D-308）

どちらも [#15](https://github.com/shuhei1101/project-index/pull/15) で dev-docs から移した配信元の読み込みと端末の設定の API が対象。
