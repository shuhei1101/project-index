# 要件

## 要望

- `run_serve` がログのハンドラを閉じた後（再起動の `os.execv` の前・停止の `os._exit` の前・`finally`）に、裏のスレッドがログを書いても、`{log_dir}/project-index.log` が開き直されて閉じられないまま残らない
- 単体テスト `tests/unit/project_index/test_serve.py::test_run_serve_when_restart` が、裏のスレッドのログの時機によらず `ResourceWarning`・`PytestUnraisableExceptionWarning` で error にならない
- 閉じた後に裏のスレッドがログを書く競合を、時機に頼らず再現する単体テストを置き、修正の前に fail・修正の後に pass する

`未確定`: 閉じた後のログの扱い（決める段: モジュール構成設計）

| 案 | 内容 |
| --- | --- |
| A | 閉じたハンドラが `emit` でファイルを開き直さない（閉じた後のログは標準エラーだけに出るか捨てる） |
| B | ハンドラを閉じる前に裏のスレッドの終わりを待つ |

推奨: A

裏のスレッドは検査・書き出しで長く動くことがあり、待つと再起動・停止が遅れるため。原因が見立てのとおりかは、設計の前に再現して確かめる。
