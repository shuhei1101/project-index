# 要件

## 要望

エージェントが `write_docs` へ `worktree` を省いて `cwd` を渡したときに、どのワークツリーへ書くかを、設計書・ツールの説明・実際の動作で一致させる。

- 原因: PreToolUse のフックの `build_updated_input` が、エージェントが入れた `cwd` をセッションの作業場所で上書きする。文書の MCP は上書き後の `cwd` で書く先を決めるため、指定した `cwd` は使われない
- 一方で、ツールの入力のスキーマには `cwd` が説明なしで出ており、エージェントは指定した `cwd` が使われるものとして呼び出せる
- 観測した事象は、セッションの作業場所が knowledge のクローン本体だったため、ワークツリーが決まらず `TargetIsCloneError` が返ったもの。エラーが返すクローン本体のパスは、配信元の設定を読む develop のワークツリー（`repo_root`）を指しており、クローン本体（`main_root`）を指していなかった
- フックの上書きは保ち、文書の MCP の全てのツールの入力のスキーマで、`cwd` の `description` に、指定しても使わないことと、ワークツリーは `worktree` で指すことを載せる。IF-1〜IF-7 の `cwd` の説明も揃える
- `TargetIsCloneError` が返すクローン本体のパスは、配信元の設定をワークツリーから読んでいても、ワークツリーの親のクローン本体にする
- `worktree` を指定してワークツリーへ書く動作と、作業場所によらず `scope` の外へ書かせない動作は変えない
- 単体・結合テストで、ツールの入力のスキーマの `cwd` の説明と、`TargetIsCloneError` のクローン本体のパスを確かめる
