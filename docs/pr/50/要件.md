# 要件

## 要望

エージェントが `write_docs` へ `worktree` を省いて `cwd` を渡したときに、どのワークツリーへ書くかを、設計書・ツールの説明・実際の動作で一致させる。

- 原因: PreToolUse のフックの `build_updated_input` が、エージェントが入れた `cwd` をセッションの作業場所で上書きする。文書の MCP は上書き後の `cwd` で書く先を決めるため、指定した `cwd` は使われない
- 一方で、ツールの入力のスキーマには `cwd` が説明なしで出ており、エージェントは指定した `cwd` が使われるものとして呼び出せる
- 観測した事象では、上書き後の作業場所がクローン本体と判定され `TargetIsCloneError` が返った。そのときのセッションの作業場所が `worktrees` に当たらなかったのかを、インターフェース定義設計で確かめる
- 修正後に、`worktree` を指定してワークツリーへ書く動作と、作業場所によらず `scope` の外へ書かせない動作は変えない
- 単体・結合テストで、決めた動作を確かめる

`未確定`: `cwd` を指定された呼び出しの扱い（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | フックの上書きを保ち、`cwd` は指定しても使わないと、ツールの `cwd` の説明・IF-6・`docs/guide/文書のMCP.md` に記載する。ワークツリーを指すときは `worktree` を指定する |
| B | フックがエージェントの入れた `cwd` を残す。`scope` の判定はセッションの作業場所で行い、書く先のワークツリーだけ指定した `cwd` から決める |

推奨: A

IF-20 の制約「上書き」は、作業場所を偽って `scope` の外を書き換えさせないために置いた。A はこの目的を保ち、ワークツリーを指す手段は既に `worktree` がある。
