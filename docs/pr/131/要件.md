# 要件

## 要望

setup がプロンプトの `documents` の行（`content/prompts/**/*.yaml`、プラグインのルートは `{ルート}/content/prompts/**/*.yaml`）を記載するとき、その行の `paths` に当たるファイルを管理用の YAML（`files.yaml` / `files.local.yaml`）に記載せず、プロンプトの文書 1 件として配信する。

- 初回（`{config}` が無く、範囲を既定の `**/*` にした場合）: 管理用の YAML の追加の候補にプロンプトの YAML が出ない
- 2 回目以降（管理用の YAML に既にプロンプトの YAML の行がある場合）: プロンプトの行の候補と一緒に、その行の削除の候補が出る
- どちらも、記載した後の `check_project` が違反と索引の同期の件数を 0 で返し、`search_docs` がプロンプトの YAML 1 つにつき文書を 1 件だけ返す

索引の同期と `project-index files` は、ほかの `documents` の行の `paths` に当たるファイルを管理用の YAML の対象から外す（インターフェース定義設計で確定。reviewer の合意: https://github.com/shuhei1101/project-index/pull/131#discussion_r4596880203）。

- `documents[].exclude[]` はファイル名だけに当たり `/` を含めないため、`content/prompts/**` を `exclude` で外す方法は取らない
- 索引の同期: 管理用の YAML のフォルダの配下でも、ほかの行の `paths` に当たり、その行の `exclude` に当たらないファイルを「管理用の YAML に無いファイル」に数えない
- `project-index files`: `--exclude-path`（`documents[].paths` と同じ書き方の glob）を加える。setup はプロンプトの行の `paths` を渡し、`project-index.yaml` がまだ無い初回でも候補の行の `paths` で外す
