# 要件

## 要望

- knowledge のテンプレート『フォルダ構成』（`template-layout`）の書式で、このリポジトリの直下からの全てのフォルダとファイルを入れ子の `entries[]` で記載した設計書 `docs/layout/LAY-73-1.yaml` を 1 枚作成する
  - 生成物・一時ファイルは `gitignore[]`・`generated_from` で、中身の種類は `content_types` で記載する
  - 配下の細かい配置を言語の規約が定めるフォルダ（`src/project_index/` など）は、`children` を記載せず `convention` で規約を指す
  - `repository` はアーキテクチャ図の `repository.repositories[].name`（`shuhei1101/project-index`）と同じ値にする
- 配信元の設定 `project-index.yaml` の `documents` に種類 `layout` を追加し、スキーマは knowledge の `schemas/design/layout.schema.yaml` を参照する
- 目次 `docs/index.yaml` に `layout/` を追加し、`docs/layout/index.yaml` を作成する
- 規約『フォルダ構成の切り方とレビュー』（`dev-folder-layout`）のレビューの観点（同じ種類が散る・種類が混ざる・まとめすぎ・共通のものが深い・管理しないもの）で、記載した設計書から今のフォルダ構成を確認する
  - 見つかった問題は、問題ごとに Issue を起票し、スコープ外に起票した番号を書く。この作業 PR ではフォルダの配置・形式を変えない
