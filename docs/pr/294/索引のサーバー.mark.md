## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 作成機能 | `create` に `new_path` があれば、`paths` の先頭から決める代わりに、正規化した `new_path` を配置先にする | `records` を持たない行だけ |
| バリデーション | `new_path` が配信元の外を指す・`matches` に該当しない（`paths` に該当しないか `exclude` に該当する）・既にあるファイルを指すときは違反にする | `rename` の `new_path` と同じ判定と文言にそろえる |
| バリデーション | `records` を持つ行の `create` の `new_path` は引数の誤りにする | - |
| エラー返却 | `InvalidArgumentError` で、違反の `path` を `operations[{i}].new_path` にする | 何も書き込まない |
| 直コミット | `commit` を指定した `create` でも同じ配置先で書き込み、コミットする | 直コミットの判定は変えない |
| SC-7 | `new_path` を指定して、フォルダの階層に glob を持つ種類の文書を作成するシナリオを追加する | - |
| IF-6 | `operations[].new_path` を `create` と `rename` で受けるキーにし、`create` の `new_path` の正常系・異常系のフローと `InvalidArgumentError` の `condition` を追加する | - |
| MOD-83・MOD-84・MOD-85 | 配置先の決め方・`create` の処理・`new_path` の説明に `create` の `new_path` を追加する | 関数を分けるか引数を追加するかはモジュール構成設計で決める |
| 既存機能への影響 | `new_path` を省いた `create` と、`rename` の振る舞いは変えない | 既存の単体・結合テストで回帰を確認する |
