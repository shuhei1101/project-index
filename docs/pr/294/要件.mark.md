# 要件

## 要望

`write_docs` の `create` の操作に、作成する文書のファイルのパス `new_path`（`rename` の `new_path` と同じく配信元の直下からのパス）を指定できるようにする。

| 指定 | 振る舞い |
| --- | --- |
| `new_path` を省く | 今と同じく、種類の行の `paths` の先頭から配置先を決める |
| `new_path` が種類の行の `paths` に該当し、`exclude` に該当せず、まだ無いファイルを指す | そのパスに文書を作成する |
| `new_path` が `paths` に該当しない（配信元の外を指すパスを含む）・`exclude` に該当する・既にあるファイルを指す | 何も書き込まずに `InvalidArgumentError`（`isError`）で断る。違反の `path` は `operations[{i}].new_path` |
| `records` を持つ行の `create` に `new_path` を指定する | 引数の誤りとして `InvalidArgumentError` で断る（要素を追加する管理用の YAML は行の `paths` の先頭で決定する） |

- `new_path` は `posixpath.normpath` で正規化してから照合し、`rename` の `new_path` と同じ判定（`DocumentTable.matches`・既にあるファイルの確認）を使用する
- 文書の ID は今と同じく `data` の ID か `ids.format` から決め、`new_path` のファイル名に ID が入らなくてもよい
- `commit` を指定した `create` でも `new_path` を使用でき、直コミットの判定（許可する種類・本文の直コミット）は今と変えない
- aituber の 2 つの種類（`portrait/*/*.yaml`（`exclude`: `portrait/*/definition.yaml`）の `asset_portrait`、`portrait/*/definition.yaml` の `portrait_definition`）で、`portrait/{キャラクター ID}/{アセット ID}.yaml`・`portrait/{キャラクター ID}/definition.yaml` へ作成できる
- `new_path` を受ける操作は `create` と `rename` になり、`update`・`replace`・`replace_text` に指定したときの扱い（今の引数の検査）は変えない
