## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 実行場所の判定 | 単体テスト（バック）・結合テスト（バック）・lint の層を、判定フローチャート『テストの実行場所』で判定して `location` に記載する | E2E テスト・非機能要件テスト・外部疎通テストは `run_all` が未確定のため記載しない |
| ランナーでの実行 | `runner` の層に、workflow を `workflow_dispatch` で起動して終わるまで待ち、失敗したときもログを取得してから失敗で終える `run_runner` を記載する | 結合テストの層は、入力の `{結合テストのパス}` を省いたときに全件を回す |
| workflow の設計 | `.github/workflows/test.yml` の入力・権限・副作用・同時実行の扱いを、インターフェース定義 `docs/interface/IF-116-1.yaml` に記載する | 書式は knowledge のインターフェース定義のテンプレート |
| workflow の作成 | インターフェース定義のとおりに、依存の導入（uv・Python）と層のテストの実行、ログの成果物へのアップロードをする workflow を作る | タイムアウトは判定フローチャート『タイムアウトの決め方』で決める |
| 手元が要るテスト | 層の中の一部のテストだけが手元でしか用意できないものを要する場合、マーカーを付けてランナーの全件実行から除く | 該当するテストがあるかは実行場所の判定で確認する |
| 手元での実行 | `run_all`・`run_one` は手元で回すコマンドのまま残す | - |
| フォルダ構成 | フォルダ構成に `.github/workflows/test.yml` のエントリを追加する | - |
| 既存機能への影響 | `src/`・`plugins/` のコードは変更しない | - |
| コスト | リポジトリは public で、標準のランナーは無料枠を消費しない | - |
