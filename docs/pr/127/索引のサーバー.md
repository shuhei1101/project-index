## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の切り分け | ランナーと同じ ubuntu の環境で、払い出して閉じたポートと閉じたばかりの接続が残るポートに `check_port` を繰り返し当て、fail の条件（ほかの接続がポートを使用しているか・bind の判定か）を特定する | 結果をこの計画書に追記してからモジュール構成設計へ進む |
| 単体テストの準備 | `test_check_port`・`test_check_port_when_time_wait` の準備を、払い出してから `check_port` を呼ぶまでの間にほかの接続にポートを使用されない構造にする | 具体的な構造は切り分けの結果で決め、MOD-89 の `unit_tests[].condition` に記載する |
| `check_port` | 切り分けで判定が原因と分かった場合だけ、uvicorn の bind と同じ判定を保ったまま修正する | 起動の入出力（`PortInUseError` のメッセージ・終了コード）は変えない |
