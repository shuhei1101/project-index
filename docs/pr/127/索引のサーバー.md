## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `test_serve.py` の準備 | autouse の fixture `_join_background_threads` を足し、各テストの後に、`project-index-` で始まる名前の生きているスレッドが無くなるまで一覧を取り直して join する（スレッドごとに 30 秒で打ち切り、残ったらその名前を出して fail させる） | `run_serve` を呼ぶテストも `_free_port` のポートを `check_port` に通すため、`check_port` のテストに限らずファイルの全てのテストに当てる。MOD-89 の `run_serve`・`check_port` の `test_setup` に記載した |
| `check_port` | 変更しない | 切り分けで、bind の判定ではなくテストの準備が原因と分かった |

## 原因の切り分け

| 観点 | 結果 |
| --- | --- |
| ランナーのログ | run 44039276591 で、`test_check_port` の行の途中に `sample` が出力されている。直前の `test_run_serve_when_restart` が起動した読み込みのスレッド（`project-index-loading`）を join しないまま、次のテストの間も動いている |
| 残っているスレッド | `test_serve.py` を流し、テストごとの開始時に `project-index-` で始まる名前のスレッドを数えた。`test_check_port`・`test_check_port_when_time_wait` の開始時に `project-index-loading`・`project-index-loading_0` が残る |
| スレッドの処理 | 監査フックで観測すると、残った読み込みのスレッドは `test_check_port` の間に `git rev-parse --show-toplevel` を subprocess で起動する。ソケットの bind・connect はテストの MainThread だけ |
| 原因 | 読み込みのスレッドが fork してから exec するまで、子プロセスがテストのソケット（`_free_port` のソケット・待ち受けのソケット）の fd を持つ。テストが閉じても子プロセスの exec まではポートが bind されたままになり、`check_port` の bind が `EADDRINUSE` になる |
| 原因の確認 | 別スレッドで exec の前に 0.5 秒止まる子プロセスを起動し、その間にソケットを閉じて `check_port` を呼ぶと、bind だけのソケット・待ち受けのソケットのどちらも `PortInUseError` になり、子プロセスの exec の後は通る |
| 手元で再現しない理由 | fork から exec までの時間が短く、ランナーより競合の幅が狭い（該当テストを 40 回流して fail なし） |
