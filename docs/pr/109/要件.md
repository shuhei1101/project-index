# 要件

## 要望

- `write_docs` の点検に使用する mdmark の CLI を、既定で mdmark の develop の最新（`github:shuhei1101/mdmark#develop`）で入れる
- 設定で、mdmark のタグ（`v{MAJOR}.{MINOR}.{PATCH}`）か commit の SHA を指定すると、そのバージョンに固定して入れる
- 入れ方の案内（global-setup の最後の応答・ガイド [docs/guide/project-indexを入れる.md](https://github.com/shuhei1101/project-index/blob/e581544/docs/guide/project-index%E3%82%92%E5%85%A5%E3%82%8C%E3%82%8B.md)）と、シナリオ [docs/scenario/SC-2.yaml](https://github.com/shuhei1101/project-index/blob/e581544/docs/scenario/SC-2.yaml) の期待値を、既定の参照と固定するときの記載方法に合わせる
- 外部ライブラリの設計書 [docs/library/LIB-7.yaml](https://github.com/shuhei1101/project-index/blob/e581544/docs/library/LIB-7.yaml) の参照（`version.current`・`source`・`pinning`）を、既定で develop の最新を参照し、タグか commit で固定できる記載にする

バージョンを固定する設定は、端末の設定のキー `mdmark_ref`（既定 `develop`。タグか commit の SHA を記載すると固定）で持つ。
global-setup は mdmark の CLI が無いときに `npm install -g github:shuhei1101/mdmark#{mdmark_ref}` を案内し、管理の MCP の `update` は `PATH` に mdmark の CLI があるときに同じ参照で入れ直す。
入れ直しに失敗しても `update` は止めず、理由を応答に入れる。
