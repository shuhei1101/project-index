## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 機能の分け方 | 文書の MCP・配信元の読み込みと検査と変換・書き込み・管理の MCP のうち配信元を扱うツール・端末の設定を、dev-docs の `features/` の分類のまま `src/project_index/` の下へ移す | 分類ごとの置き場所はモジュール構成設計で決める |
| 文書の MCP | 7 つのツールの名前・入力・出力・エラーを今の dev-docs と変えずに移す | ツールの説明は `content/prompts/` から移す |
| 管理の MCP | `check_project`・`reload`・`try_convert`・`write_nav`・`status` を移す。dev-docs の画面のサーバーに残すツールとの境界は shuhei1101/dev-docs#163 のインターフェース定義設計と揃える | - |
| 読み取り API | Issue #14 の 6 つの用途を、配信元の ID・文書のパス・リビジョンを入力に取る汎用の HTTP の API にする。dev-docs の画面のタブ・サイドバー・画面の状態に寄せた項目は出力に含めず、画面の構成（`nav`）の元と変換した Markdown・メタデータ・変換の失敗を返す | 規約『複数リポジトリのAPI契約』。契約はインターフェース定義に置き、dev-docs#163 のモックはそれに沿わせる |
| 端末の設定の API | 今の `GET`・`PUT /_api/settings/sources` と同じ丸ごとの取得・保存を移し、保存した後に読み直した配信元の状態を返す | 1 行ずつの API は #10 |
| 配信元の設定の既定のファイル名 | 名前で探す処理・雛形・設計書・使い方の例の既定を `project-index.yaml`・`project-index.local.yaml` にする | 今の `dev-docs.yaml` の移行は [要件](./要件.md) の `未確定` |
| 待ち受け | 1 プロセス・1 ポート（`PROJECT_INDEX_PORT`、既定 8786）で `/mcp`・管理の MCP・読み取り API を待ち受ける | [要件](./要件.md) の `未確定`。同じ端末に限るかは非機能要件の通信（NFR-2）で決める |
| 状態のフォルダ | 会話記録の SQLite・リビジョンの書き出し・変換の結果を CFG-1 の `state_dir` に置く | dev-docs の状態のフォルダは引き継がない |
| shuhei1101/dev-docs#119 の修正 | 1 回の要求の中で ref の解決とスキーマの読み込みを繰り返さない処理と、所要時間のテストを処理と一緒に移す | - |
| 依存 | 移す処理が使う依存（fastapi・mcp・uvicorn・ruamel.yaml・jsonschema・pydantic など）を `pyproject.toml` に加える | 入れ方・起動に影響するため、「project-index を入れる」の単一ユースケースを影響するユースケースに挙げる |
| 既存機能への影響 | このリポジトリには移す機能の利用者がまだ無い。dev-docs の利用者の接続先の付け替えは shuhei1101/dev-docs#163 の反映作業が担う | - |
| 性能 | 移した後に、#119 の 3 つの要求で所要時間を測り、#119 の本文の表の値と比べて記録する | 値は非機能要件に書く |
