# 要件

## 要望

`.github/workflows/test.yml` の `paths` の各値に、`tests/integration/` の下のファイルに続けて `::{関数}` を指定でき、指定した関数のテストだけをランナーで回せる。

- 受け付ける値: `tests/integration/` の下のファイルかフォルダ（今と同じ）と、`tests/integration/` の下の `.py` のファイルに `::{関数}` を 1 つ続けたもの（parametrize の `[{id}]` を末尾に含む）
- `paths` に `tests/integration/server/test_write_docs.py::test_normal_when_text_edits_ref_path` を指定して起動すると、その関数のテストだけが回り、実行の結論が `success` になる
- 層のフォルダの外・`..`・空白以外の区切り（`,`・`;`）を含む値と、ファイルの後ろ以外の位置の `:` を含む値は、今と同じくテストを回さずに失敗で終える
- `paths` の値は、シェルのパス名の展開（`[{id}]` の `[`〜`]`）を受けずに pytest の引数になる

`未確定`: parametrize の `[{id}]` の中に受け付ける文字（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `[{id}]` の中の `.`・`,` も受け付け、`..`・`,` の検査をノード ID の `[`〜`]` の外にだけ適用する | parametrize の id の値（`1.5`・`a,b` など）をそのまま指定できる | 検査の case のパターンが増える |
| B | `[{id}]` の中も今の検査（`..`・`,`・`;`）に適用し、該当する id は指定できないままにする | 検査が今のパターンに `::` の許可を追加するだけで済む | `..`・`,` を含む id の関数は、関数名までの指定（id の全件）に広げて回す |

推奨: B

空白は `paths` の区切りのため、どちらの案でも id に含められない。
`..` を外へ出る値の検査から除外すると検査が崩れやすく、id の全件に広げても関数の単位の範囲に収まる。
