## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `paths` の検査 | 値ごとに、`{tests/integration/ の下のパス}` か `{tests/integration/ の下の .py のファイル}::{関数}`（末尾に `[{id}]` を 1 つ持てる）だけを受け付け、`..`・`,`・`;` と、それ以外の位置の `:` を含む値はテストを回さずに失敗で終える | `[{id}]` の中も `..`・`,`・`;` の検査を適用する |
| シェルのパス名の展開 | `paths` を空白で分けた値を、パス名の展開を止めて（`set -f`）pytest の引数に指定する | `[{id}]` が `tests/integration/` の下のファイル名に一致して置き換わらないようにする |
| インターフェース定義 | IF-116-1 の `paths` の説明・制約「回す範囲」にノード ID を加え、正常系（ノード ID を指定）と、異常系（結合テストのパスが層のフォルダの外）の例にファイルの後ろ以外の `:` を加える | - |
| テスト実行方法 | TP-1 の TL-2 の `{結合テストのパス}` にノード ID を指定できることを記載する | 更新ドキュメント |
| ランナーでの確認 | 規約『Git フックと CI で動かすもの』の手順で、作業ブランチへの `push` を一時的に `on:` に加え、`paths` にノード ID と弾く値を指定して動かし、確認した後に戻す | IF-116-1 は対応テストファイルを持たない |
