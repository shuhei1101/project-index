## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| リビジョンの書き出しの時期 | 配信元の読み込み・読み直しの後に、配信元ごとの `default_ref` の commit の書き出しを裏で先に済ませ、最初の問い合わせの中で `git archive` を呼ばないようにする | 書き出しの範囲（作業ツリー全体か配信元の範囲だけか）はモジュール構成設計で決める |
| 上限を超えたときの応答 | 書き出しが上限を超えて止まったときは、500 ではなく、止めた処理（リビジョンの書き出し）と理由（上限の秒数）を持つエラーの応答を返す | 状態コードとエラーの型はインターフェース定義設計で決める |
| `GIT_ARCHIVE_TIMEOUT_SEC` | 先に書き出す直し方で最初の問い合わせが上限に当たらなくなるかを確かめ、値は変えない。変える場合は規約『資源の値の決め方』で大きい配信元を測り直して導く | 由来は要件の `## 変更箇所の由来` |
| `reload` の応答の時点 | 一覧を差し替えた時点で応答し、検査は起動の後と同じく裏のスレッドで流す（要件の `未確定` の推奨 A） | `PUT /settings/sources` も同じ経路を通る |
| `status` | 読み直し・検査の最中であることと、裏のリビジョンの書き出しの最中であることを表す値を持たせ、markdown にも出す | 値の名前はインターフェース定義設計で決める |
| `reload` の返却の `sources[]` | 検査の前の値（`sync: null`）を返すことを IF-9 とガイドに書く。型は変わらないため破壊的変更は付けない見込み。意味の変化を破壊的変更とするかはレビューで確かめる | - |
| ガイド | `docs/guide/管理のMCP.md` の `## reload` に応答の時点と、`status` で済んだかを確かめる方法を書く | - |
