### 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 深い管理用の YAML の範囲 | ほかの有効な `records: files` の行の管理用の YAML のうち、判定する管理用の YAML より深いフォルダにあるものの、そのフォルダの配下を候補から除外する | 単一ユースケース設計で確定 |
| 記載しないフォルダ | `documents[].exclude[]` に `/` を含む値を記載したときは、`paths` の基準からのパスの glob として適用する。`/` を含まない値は今のとおりファイル名に適用する。スキーマの `pattern` も合わせる | 同上 |
| `project-index files` | 候補の判定を `unindexed_files` と同じにする（`--exclude` に `/` を含む値を指定できる） | - |
| setup の初回に作るファイル | 判定は変えない（setup が管理用の YAML に記載する） | 単一ユースケース設計で確定 |
| 既存の配信元への影響 | 今の `exclude`（`/` を含まない値）と、ほかの行の文書を数えない判定はそのまま保つ | - |
