# 要件

## 要望

端末の負荷が高い間（load average 18〜21・8 コア）も、リビジョンの書き出し（`SnapshotStore.checkout` の `git archive --format=tar {commit}`）が待ち時間の上限で止まらず、`search_docs`・`write_docs`・`list_changes` が配信元の文書を返す。

- 負荷の高い端末で `git archive` の所要時間を測り、規約『資源の値の決め方』の下流を待つタイムアウトで待ち時間の上限を導き直す。導出の元の値と導き方を設計書 MOD-86 の `GIT_ARCHIVE_TIMEOUT_SEC` の `notes` に記載する
- `git archive` だけに別の上限（`GIT_ARCHIVE_TIMEOUT_SEC`）を持たせ、`run_git` の `timeout` で指定する。他の git の呼び出しは `GIT_TIMEOUT_SEC` のまま待つ
- 反映作業の確認のスクリプト（[確認.py](https://github.com/shuhei1101/project-index/blob/6f739dd31d138cff47628e23fd7389ac7217275b/docs/pr/19/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/%E7%AB%AF%E6%9C%AB%E3%81%AE%E8%A8%AD%E5%AE%9A%E3%81%AE%E9%85%8D%E4%BF%A1%E5%85%83%E3%81%AE%E3%83%91%E3%82%B9%E3%81%AE%E4%BF%AE%E6%AD%A3/%E7%A2%BA%E8%AA%8D.py)）は修正しない。再実行すると ok になり、照合の仕方に誤りは無い
