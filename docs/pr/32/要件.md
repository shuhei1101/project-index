# 要件

## 要望

ソースコード・テストのファイルを配信元 project-index の文書として配信し、設計書との関連を張る。

| 項目 | 終わりの条件 |
| --- | --- |
| 管理用の YAML | `src/files.yaml`・`tests/files.yaml`・`plugins/project-index/files.yaml` に、それぞれの配下の `.py` のファイルが 1 ファイル 1 行で並ぶ（`__init__.py` は除く） |
| 配信元の設定 | `project-index.yaml` の `documents[]` に、3 つの管理用の YAML を `records: files`・`body_file: path` の行で加え、配信しない `.py` でないファイルを行の `exclude` で外す |
| `implements` | モジュール構成の設計書の要素の `container` が指すファイルの行が、その設計書への `implements` を持つ |
| `tests`（単体） | モジュール構成の設計書の `test_files` が指すテストのファイルの行が、その設計書が指すコードの行への `tests` を持つ |
| `tests`（結合） | インターフェース定義の `test_file` が指すテストのファイルの行が、そのインターフェース定義への `tests` を持つ |
| 検査 | `check_project` が、加えた行で違反を出さず、3 つの管理用の YAML のフォルダで索引に無いファイルを数えない |
| 辿れること | `trace_related` をモジュール構成の設計書から `direction: in` で呼ぶと、実装とテストのファイルが返る |

`plugins/project-index/hooks/` のフックのコードは Issue の本文の対象（`src/project_index/`・`tests/`）に無いが、`tests/unit/plugins/` のテストの `tests` の関連先になるため対象に含める。

設計書と 1 対 1 で対応しないファイル（`conftest.py` など）の行は、`implements`・`tests` を持たない。
