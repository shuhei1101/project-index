## 要望

- `project-index.yaml` の設計書の種類の行の `schema` を、knowledge の `schemas/design/{種類}.schema.yaml` を指す参照（`source: knowledge`・`path`・`ref`）にする。全ての行が同じ `ref`（knowledge の `design-schemas/v{バージョン}` のタグ）を指す
- 管理用の YAML の行（`files_guide`・`src`・`tests`・`plugin`）の `schema` を、knowledge の `schemas/knowledge-files.schema.yaml` を指す参照にする
- `schemas/` の設計書のスキーマのコピー（種類ごとの `{kind}.schema.yaml`・`common.schema.yaml`・`index.schema.yaml`・`glossary.schema.yaml`）と、使用しない `phase.schema.yaml`・`files.schema.yaml`、取り込んだバージョンを持つ `ai-monitor-version.ini` を削除する
- 設計書・目次・管理用の YAML が、参照先の knowledge のスキーマの検査に合格する（`check_project` で違反が 0 件）
- `src/files.yaml`・`tests/files.yaml`・`plugins/project-index/files.yaml` の 1 行目の `$schema` が、削除した `schemas/files.schema.yaml` を指さない
- 配布する設定のスキーマ（`project-index.schema.json`・プロンプトのスキーマとその `$ref` 先の共通の型）を 1 つのフォルダに集め（`templates/files.schema.yaml` は #75 の範囲のため除く）、設計書のスキーマと同じフォルダに混ざらず、同じ名前で別の中身を持つファイルが無い
- フォルダ構成の設計書 [LAY-73-1](../../layout/LAY-73-1.yaml) の `schemas`・`templates`・`ai-monitor-version.ini` のエントリが、変更後のフォルダと一致する
- 配布する設定のスキーマの配置先は `schemas/` にする。設計書のコピーを削除した `schemas/` へ `templates/prompt.schema.yaml`・`templates/common.schema.yaml` を移し、`project-index.schema.json` はパスを変えない

- 設計書を knowledge の `design-schemas/v9.2.0` の検査に合格させる書き換えも、この作業 PR で行う。AI Monitor の変換（`design_docs convert`）で移せる分を移し、残りは次のとおりにする
  - 関連（`refs`）の `type`・`when` は、変換で埋めた値を残さず、文書ごとに内容を判断して書く
  - knowledge のスキーマに無い項目（モジュール構成の `directory`、アーキテクチャ図の `repository.layout`、用語集の `tags`、MOD-34 のメソッドの `callers`）は、中身が物理ファイルごとのモジュール構成・LAY-73-1 などの他の設計書にあることを照合してから削除する
