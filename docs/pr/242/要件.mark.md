# 要件

## 要望

- 項目のパスの 1 つの区切りの中で、引用符で囲んだキー `["{キー}"]`（例 `notes["mcp/server.py の補足"]`）を、`.`・`[`・`]` を含むマップのキーとして読む
  - `get_field`・`set`・`unset`・`add_to`・`remove_from`・`text_edits[].field` など、項目のパスを解釈する全ての操作で同じ読み方にする
  - 引用符の中の `"`・`\` は `\` でエスケープする
  - `[{キー}]`（引用符なし）は今までどおり配列の要素を選ぶ
- `#` で始まらない `unset` の要素が文書の項目へ解決できない（項目が無い）ときに、呼び出し元が文書の変わらなかったことを知れるようにする

`未確定`: 解決できない `unset` の返し方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `unset.{パス}` の違反にして書き込まない（#162 の `#` で始まるパスと同じ扱い） |
| B | 書き込みは通し、その操作の結果に、解決できずに何もしなかった `unset` の要素を返す（文書が変わらなければ `version` も変わらないことを IF-6 に明記する） |

推奨: B

IF-6 は「項目が無ければ何もしない」を今の仕様として定めており、A は今通る呼び出し（無い項目を念のため消す `unset`）を断る破壊的変更になるため。
B なら今の呼び出しを断らずに、消えていないことを結果から読める。
