# 要件

## 要望

- `.` を含むマップのキーを項目のパスで指せるようにする
  - 既存の `#` で始まる参照の型の項目のパスの `[{キー}]`（`.` や空白を含んでも 1 階層）で指せる。`unset: ["#notes[mcp/server.py の補足]"]` で削除し、`set: {"#notes[{新しいキー}]": ...}` で追加できる（develop の `fields.py` の `delete_field` に MOD-3038-6 の `notes` を当てて、キーが消えることを確かめた）
  - 新しい書き方は足さず、制約「unset の項目のパス」とガイド『文書のMCP』の `unset` の説明から、`.` を含むキーをこの書き方で指すことを案内する
- 違反にせず何もしない操作は、その操作の項目のパスと理由を `results[].skipped` に返却する。対象は次の 4 つ（起点 Issue の `unset` と、#151 と同じ「成功を返すのに文書が変わらない」型の `remove_from` の経路）
  - `#` で始まらない `unset` の要素の項目が無い
  - `#` で始まらない `remove_from` のキーの項目が無い
  - `x-key` を持たない配列の `remove_from` の値に等しい要素が無い
  - 共通のキー `tags`・`main_tags` の `remove_from` に無い名前を指定した
  - 違反にはしない。IF-6 は「何もしない」を今の仕様として定めており、違反にすると今通る呼び出し（無い項目・要素を念のため消す操作）を断る破壊的変更になるため
