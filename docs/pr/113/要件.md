### #102 検索の範囲

- 手順 3 の検索できるようにするファイルの既定を `**/*` にする
- Git が無視するファイルを除外するかの既定を「除外しない」にする
- `.git`・`node_modules`・`__pycache__`・`.venv`・`.claude/worktrees` の下は、今と同じく辿らない

`未確定`: `project-index files` の除外の条件（生成物・ロック・バイナリ・ベンダーのコード・再エクスポートや空の `__init__`）の扱い（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | バイナリ（本文を文字列として読めないファイル）と空のファイルだけを除外の条件に残し、他は記載する | 文字列のファイルは全て検索できる | ロック・生成物の行が管理用の YAML に増える |
| B | 今の除外の条件を全て残す | 管理用の YAML の行が増えない | Python などのコード以外にも、ロック・生成物は検索できないまま残る |
| C | 除外の条件を全て解除する | 範囲のファイルが全て記載される | バイナリの行に付けるメタデータを本文から作れない |

推奨: A

ユーザーの要望は「どんなファイルでも検索できる」で、バイナリと空のファイルは検索できる本文を持たないため記載しても検索の対象にならない。
SC-5 のシナリオは案 A で記載した。
除外の条件は `check_project` の `unindexed_files` と同じ判定のため、案 A・C は `check_project` の結果も変わる。

### #107 関連の候補

- 実装のパスを持つ設計書の種類とキーを、配信元の種類のスキーマからコードのパスを持つキーを探して既定の回答として示す
- 設計書・文書の本文に出るコードのパスとリンクを取り出し、関連の候補にする
- 2 回目以降の setup で、既に管理用の YAML にある行のうち関連を持たない行にも候補を出す
- 関連の `type` は判定フローチャート『関連の張り方』で選び、設計書 → コードの向きは記載しない（`templates/files.schema.yaml` の `related`）

`未確定`: 本文からパスとリンクを取り出す手段（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `project-index` の CLI のサブコマンドで機械的に取り出し、候補を出力する | `project-index outline` と同じく、エージェントが参照の方法を考えずに済む | CLI のサブコマンドとテストが増える |
| B | エージェントが本文を読んで候補を作る | project-index のコードを変えない | 参照する量がファイルの数に比例し、取りこぼしがエージェントで変わる |

推奨: A

[#106](https://github.com/shuhei1101/project-index/pull/106) で、機械的に取り出せる情報は project-index が用意する手段の出力を使用すると決めている。

### #108 alias-inject の設定との突き合わせ

- setup の手順 6 で端末の設定の `sources[]` に記載した後、alias-inject の端末の設定があり、`{config}` が `alias_type` を持つ documents の行を持つときに、`global.repositories[]` と `{config}` を突き合わせる
- `{config}` と同じフォルダの別の名前の設定のファイルを指す行があれば、その行の `config` を `{config}` にする修正の候補を示す
- `{config}` のフォルダを指す行が無ければ、`{config}` を指す行の追加の候補を示す
- 了承されたら、`settings.yaml.bak-{日時}` のバックアップを取ってから書き換える
- alias-inject の端末の設定が無いときは、候補を出さず、設定を作らない

`project-index migrate` は設定のファイルを改名しないため、突き合わせは setup だけに置く。
配信元の設定のファイルを改名した利用者は、`sources[].config` を直すために setup を実行し直すため、そこでずれに気付ける。

### #110 メタデータの偏りの洗い出し

- 手順 4 で仮のメタデータを付けた後に、次を洗い出して、記載の前に示す表へ見直しの候補として出す
  - ほぼ同じ `description` を持つファイルの組
  - 1 件にしか付いていないタグ
  - 半数以上のファイルに付いているタグ
- 洗い出しは `project-index` の CLI のサブコマンドで行い、エージェントは出力を使用する
- 「ほぼ同じ」の判定と値は、インターフェース定義設計で規約『資源の値の決め方』に沿って決める
