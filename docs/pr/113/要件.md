### #102 検索の範囲

- 手順 3 の検索できるようにするファイルの既定を `**/*` にする
- `.git`・`node_modules`・`__pycache__`・`.venv`・`.claude/worktrees` の下は、今と同じく辿らない
- Git が無視するファイルは、コミットする運用（`storage.type: git`）では `default_ref` から配信できないため、聞かずに除外する
- ローカル運用（`disk`）と Git 管理外の配信元では、Git が無視するファイルを既定で含め、`.env`・`.env.*` の名前のファイルだけ既定で除外する（ユーザーの確認で決定。[確認ログ](./確認ログ.yaml)）

- `project-index files` の除外の条件は、バイナリ・空のファイル・`*.local.*` の名前のファイルだけにする。生成物・ロック・ベンダーのコードは記載する（IF-17。`check_project` の `unindexed_files` も同じ判定）

### #107 関連の候補

- 実装のパスを持つ設計書の種類とキーを、配信元の種類のスキーマからコードのパスを持つキーを探して既定の回答として示す
- 設計書・文書の本文に出るコードのパスとリンクを取り出し、関連の候補にする
- 2 回目以降の setup で、既に管理用の YAML にある行のうち関連を持たない行にも候補を出す
- 関連の `type` は判定フローチャート『関連の張り方』（管理用の YAML の行は規約『ドキュメント管理』の `files-yaml-04`）で選び、設計書 → コードの向きは記載しない（`templates/files.schema.yaml` の `related`）
- 本文由来の候補の `type` は次で決める

  | 指す側 | 指される側 | 候補を付ける行と `type` |
  | --- | --- | --- |
  | 実装のパスを持つ種類（既定の回答の種類）の設計書 | 管理用の YAML の行のコード | 指される側の行に `implements`（設計書を指す） |
  | それ以外の種類の設計書 | 管理用の YAML の行 | 指される側の行に `see_also`（設計書を指す） |
  | 管理用の YAML の行の文書 | 配信元の文書 | 指す側の行に `see_also` |

本文からパスとリンクを取り出す手段は、`project-index links`（IF-113-1）にする。
[#106](https://github.com/shuhei1101/project-index/pull/106) で、機械的に取り出せる情報は project-index が用意する手段の出力を使用すると決めている。

### #108 alias-inject の設定との突き合わせ

- setup の手順 6 で端末の設定の `sources[]` に記載した後、alias-inject の端末の設定があり、`{config}` が `alias_type` を持つ documents の行を持つときに、`global.repositories[]` と `{config}` を突き合わせる
- 行と `{config}` は、Git の配信元では同じ Git のリポジトリ（`git rev-parse --git-common-dir` が同じ）か、Git 管理外の配信元では同じフォルダかで対応させる（メインのリポジトリとワークツリーのどちらで登録しても重複の行を作らない）
- 対応する行の設定のファイルの名前が `{config}` と違えば、行が指すフォルダは変えずに、ファイル名を `{config}` の名前にする修正の候補を示す
- 対応する行が無ければ、`{config}` を指す行の追加の候補を示す
- 了承されたら、`settings.yaml.bak-{日時}` のバックアップを取ってから書き換える
- alias-inject の端末の設定が無いときは、候補を出さず、設定を作らない

`project-index migrate` は設定のファイルを改名しないため、突き合わせは setup だけに置く。
配信元の設定のファイルを改名した利用者は、`sources[].config` を直すために setup を実行し直すため、そこでずれに気付ける。

### #110 メタデータの偏りの洗い出し

- 手順 4 で仮のメタデータを付けた後に、次を洗い出して、記載の前に示す表へ見直しの候補として出す
  - ほぼ同じ `description` を持つファイルの組
  - 1 件にしか付いていないタグ
  - 半数以上のファイルに付いているタグ
- 洗い出しは `project-index skew`（IF-113-2）で行い、エージェントは出力を使用する
- 確認の時点の記録（`checkpoint`）を持つ配信元では、`--only-draft` で追加・見直した行を含む組だけを比べ、前回までに断った組を再び出さない
- 1 件だけのタグに出たタグは、半数以上に付くタグに出さない
- 「ほぼ同じ」は、`description` の文字 bigram の Dice 係数が 0.9 以上（導いた記録は [しきい値の測定](./しきい値の測定/README.md)）
