# 要件

## 要望

起動の直後、裏の検査（配信元ごとの索引の同期と nav の検査）が続いている間でも、利用者が dev-docs の画面で開いた配信元の文書の一覧が、裏の検査との CPU の取り合いで待たされずに返る。

- 測り方: [Issue #145](https://github.com/shuhei1101/project-index/issues/145) と同じ手順（PoC PR [#153](https://github.com/shuhei1101/project-index/pull/153) の `poc/run.sh` の起動 1 と同じ条件。端末の設定の複製・空の状態フォルダで起動し、約 5 秒後から dev-docs の画面で 14 件の配信元を順に開く）で、配信元ごとの画面の 1 回目の秒数（dd2 のスクリプトの出力）を測る。測った時点の配信元の commit を計測ログに残す
- 基準: どの配信元の画面の 1 回目も、dev-docs の画面の打ち切り（45 秒）に当たらず、次の上限以下。上限は、裏の検査を止めた PoC の起動 2（run2a・run2b）の大きい方に、起動 2 同士の最大の差 2.4 秒を足した値
- 測る条件: 画面を開いていた間の負荷の平均（`/proc/loadavg` の 1 分値）が 12 以下で、計測の最中に配信元の develop が進まない回だけで判定する。外れた回と上限を超えた回は測り直し、測り直しても超える配信元があればユーザーに相談する（確認ログ『計測で dev-docs 以外の配信元が上限を超えた扱い』）
- 裏の書き出しを残す目的（配信元ごとの最初の問い合わせを、要求の中の書き出しで時間切れにさせない。[#85](https://github.com/shuhei1101/project-index/issues/85)）は保つ

| 配信元 | 上限 |
| --- | --- |
| dev-docs | 基準から除外（1 回目の配信元の読み込みの完了待ちは #160 で扱う。確認ログ『計測で dev-docs が上限を超えた扱い』） |
| claude-balancer | 8.3 秒 |
| aituber | 7.1 秒 |
| knowledge | 7.4 秒 |
| mdmark | 13.3 秒 |
| ai-monitor | 23.3 秒 |
| voice-input | 6.7 秒 |
| gui-support | 4.9 秒 |
| mindstella | 13.8 秒 |
| observability | 5.6 秒 |
| project-index | 8.7 秒 |
| alias-inject | 5.1 秒 |
| rule-inject | 6.2 秒 |
| shuhdev-gateway | 6.3 秒（確認ログ『測り直しでも shuhdev-gateway が上限を超えた扱い』で、計測の最大を含む値に見直した） |

待ちの原因は PoC 検証で確定した（[索引のサーバー](./索引のサーバー.md) の `## PoC 結果`）。
`SourceChecks.refresh_later` が配信元ごとに 1 スレッドで 14 件を同時に検査し、要求の中の書き出し（`tarfile` の展開）と文書の読み込みが GIL を取り合って待つ。
裏の書き出しは検査の後に始まるため、#145 の待ちに関わっていない。
検査を配信元の単位で順に流して応答中は次の検査を始めない変更（PoC の fix1）では、長い 1 件の検査と重なった配信元が延びたため、検査との取り合いの除き方は設計の工程で決める。
