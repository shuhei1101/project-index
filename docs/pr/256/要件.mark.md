# 要件

## 要望

- dev-docs の画面のサーバーが、HTTP の API で配信元の文書を作成・部分更新・置き換え・改名・削除できる
  - 操作の種類と検査は `write_docs`・`delete_docs` と同じにし、検査に合格しなかった要求はどのファイルも書き換えずに違反を返却する
  - 読み取り API・端末の設定の API と同じく `127.0.0.1` だけで待ち受け、別のオリジンからのブラウザの要求は断る
- その API の書き込みは直コミットとして、コミットするブランチのワークツリーへ書き込み、コミットしてプッシュする
  - 直コミットできる種類とブランチは、今の配信元の設定の `direct_commit` に従う
- 1 回の要求に複数の文書の書き込みと削除を並べ、全てを 1 つのコミットにまとめてプッシュできる
  - 1 つでも検査に合格しなければ、どれも書き込まずコミットしない
- 作業場所を持たない要求（画面のサーバーからの要求）で直コミットを許可するかを、利用者が端末ごとに決められる
  - 許可していない端末・配信元では、要求を断り、許可の設定の場所を伝える
- 文書の MCP の `write_docs`・`delete_docs` と、作業場所の glob で決定する今の直コミットの許可は変えない

- 書き込みの API は `POST /sources/{source}/commits` の 1 つとし、書き込み（`writes`）と削除（`deletes`）とコミットの説明を 1 回で受けて、検査・書き込み・コミット・プッシュまでする（入出力は [画面のサーバーからの直コミットの書き込み](https://github.com/shuhei1101/project-index/blob/develop/docs/interface/IF-38.yaml)）
- 作業場所を持たない要求の直コミットの許可は、端末の設定の `sources[].direct_commit.write_api_kinds`（書き込みの API から直コミットできる種類の ID の並び。既定は空で、どの種類も直コミットできない）に記載する
  - 配信元の設定の `direct_commit.kinds[]` に無い種類は使用せず、`sources[].direct_commit.kinds` と同じく警告を返却する
  - 省けば今と同じ振る舞いになる任意のキーのため、端末の設定の `version` は上げず、移し替えは要らない
