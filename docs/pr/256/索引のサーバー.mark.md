## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 書き込みの API | 画面のサーバーが呼ぶ HTTP の API を追加し、`write_docs` と同じ操作・`delete_docs` と同じ削除を並べて受け、`write_docs` と同じ検査に合格させてから直コミットする | `POST /sources/{source}/commits` |
| 一括のコミット | 1 回の要求の書き込みと削除を、コミットするブランチのワークツリーで 1 つのコミットにまとめてプッシュする。1 つでも検査に合格しなければ何も書き込まない | 失敗したときの戻しは `write_docs` の直コミットと同じ |
| 直コミットの許可 | 作業場所を持たない要求で直コミットできる種類を、利用者が端末の設定の `sources[].direct_commit.write_api_kinds` で配信元ごとに決める。許可が無ければ断り、設定のキーを返却する | 既定は空。端末の設定の `version` は上げない |
| 権限・認可 | 読み取り API・端末の設定の API と同じく `127.0.0.1` で待ち受け、`require_same_origin` で別のオリジンのブラウザの要求を断る | - |
| エラー返却 | 検査の違反・直コミットの失敗は `write_docs` と同じ内容を HTTP の応答で返却する | ステータスはインターフェース定義設計で決める |
| 既存機能への影響 | 文書の MCP の `write_docs`・`delete_docs` と、作業場所の glob による直コミットの許可は変えない | - |
