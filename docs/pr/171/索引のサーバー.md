## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 行の読み込みとの取り合い（#160） | 起動の後の行の読み込みのうち、待っている要求が指さない行を、要求の応答中と読み込み待ちの間は #147 の関所（`BackgroundGate`）で休ませる。休ませる箇所は `_validate` の文書の行ごとの `_schema_violation` と、`_row_schemas` の行ごと | PoC の構成 4。単独ではほかの配信元へ待ちが移るため、下の行の CPU の削減と組み合わせる |
| 要求の中の書き出し（#160） | `default_ref` の文書の一覧は、commit を書き出さず、ls-tree の blob のパスと `git cat-file --batch` で読み込む。blob のキャッシュ（`_blobs`・`_revision_files`）はそのまま使用する | PoC の構成 2。`## 変更箇所の由来` の判定。裏の書き出しは、書き出しを使用する文書の取得・検索のために残す（#85 の目的を保つ） |
| YAML の読み込み（#160・#161） | C 拡張（`ruamel.yaml.clib`・`pure=False`）で読み、字句の解析で読み込めなかったファイルだけ pure で読み直す | PoC の構成 3b。依存の追加の採否はライブラリ選定で決定する |
| スキーマの読み込みと検査（#160） | スキーマの読み込み（`read_schema_ref`）と `check_schema` の結果を、参照先と内容のハッシュで行をまたいで保持する | PoC の構成 6 |
| 2 回目の照合（#161） | `collect_files` の照合の結果を、commit・配信元・行の定義ごとに保持する | PoC の構成 5 |
| 性能 | 読み取り API の文書の一覧の応答時間が、[要件](./要件.md) の基準以下 | 基準は要件の `## 要望` |

結論: 成立（全部入りの構成）。
#160 の待ちの原因は、起動の直後に 10 本のスレッドで同時に読み込む配信元の行との GIL の取り合い。
行の CPU を C 拡張とスキーマの保持で減らし、要求が指さない行を応答中に休ませ、`default_ref` を書き出さずに読み込むと、取り合いがほかの配信元へ移らずに解消した。
#161 の 1 回目は YAML の読み込み、2 回目は `collect_files` の照合が占め、C 拡張（読めないファイルだけ pure）と照合の保持でそれぞれ半分以下になった。
C 拡張は依存の追加（`ruamel.yaml.clib`）が要り、採否はライブラリ選定で決定する。

最小再現コードの要点（[#174](https://github.com/shuhei1101/project-index/pull/174) の diff）:

- `src/project_index/features/documents/store.py` の `_poc_load_catfile`・`_PocCatFile`: ls-tree の blob のパスを `walk_files` と同じ判定で絞り、`git cat-file --batch` を常駐させて blob の内容を `documents_from_text`（`read_body` に cat-file）へ指定する
- `src/project_index/features/sources/registry.py` の `_next_row`（構成 1a）と `LOAD_WORKERS`（構成 1b）、`row_load` の経過と CPU の記録
- `src/project_index/poc_timing.py` の `row_unit` と `sources/service.py` の `_validate`・`_row_schemas`（構成 4）: 待っている要求が指さない行の `_schema_violation` を、関所の裏の処理の 1 件にする。`read/route.py` で読み込み待ちの間も応答中に数える
- `src/project_index/shared/yaml_io.py` の `load_yaml`（構成 3b）: `YAML(typ="safe", pure=False)` で読み、例外のときだけ pure で読み直す
- `sources/service.py` の `_ref_reader`・`_check_schema`（構成 6）と `documents/store.py` の `_load_revision_table`（構成 5）: 参照先・内容のハッシュ・commit と行の定義をキーにした保持
- `poc/run.sh`・`poc/analyze.py`・`poc/compare.py`・`poc/equal.py`・`poc/equal2.py`: 起動 2 の条件（裏の検査と書き出しを止める）で 14 件を 2 回ずつ API で取得し、内訳と中央値、同じ commit での応答の一致を出す
