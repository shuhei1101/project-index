## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 待ちの内訳 | #147 の後の develop で、読み取り API の応答時間と、配信元の読み込みの完了待ち・要求の中の書き出し・`_load_table` の読み込みの内訳を再計測する | PoC 検証で行う |
| 配信元の読み込みの完了待ち（#160） | 開いた配信元の読み込みを、ほかの配信元の読み込みより先に済ませ、要求が待つ時間を短くする | 方法は内訳を測った後に設計の工程で決定する |
| 要求の中の書き出し（#160） | `default_ref` の最初の問い合わせが、要求の中の `git archive` を前提にしない読み込み方にする | `## 変更箇所の由来` の判定。裏の書き出しを残す目的（#85）は保つ |
| 1 回目の読み込み（#161） | 文書の多い配信元の `_load_table` の読み込みの CPU 時間を短くする | 内訳を測った後に設計の工程で決定する |
| 2 回目の確認（#161） | 変わったファイルだけを読み込み直すキャッシュの確認を保ったまま、ファイルごとの `stat` の確認の時間を短くする | 同上 |
| 性能 | 読み取り API の応答時間が、[要件](./要件.md) の基準以下 | 基準は `未確定`（決める段: PoC 検証） |
