# 要件

## 要望

既存の応答のキーを残したまま、読み取り API の 4 つのエンドポイントへ次の入出力を追加する。
特定の使い手に合わせない構造にし、名前・クエリの形は設計で決める。

| エンドポイント | 追加する入出力 | 終わりの条件 |
| --- | --- | --- |
| GET `/sources/{source}/docs`（IF-24） | 文書ごとの値（YAML を読み込んだもの、行の文書は行の値）と、内容が変わると変わるバージョン | 1 回の要求で、リビジョンの全ての文書の値とバージョンを受け取れる。クエリで求めたときだけ返す構造にしてよい |
| GET `/sources/{source}/docs/{path}`（IF-25） | `records` の行の文書を文書の ID で 1 つに選ぶ指定 | 本文のファイルを持たない行の文書を、文書の ID で 1 つに選んで取得できる |
| GET `/sources/{source}/search`（IF-28） | `items[]` の文書の ID | 検索の結果の文書の ID を文書の取得に渡すと、その文書を 1 つに選べる |
| GET `/sources/{source}/config`（IF-23） | 配信元の設定の `diff` と、`documents[]` の行ごとの `$ref` を解いた種類のスキーマ | 差分で無視するキーと、絞り込みのフィールドの一覧に使える解いたスキーマを受け取れる。解いたスキーマはクエリで求めたときだけ返す構造にしてよい |

解いたスキーマに循環する参照（`$ref` のまま残る）があるときは、最上位の `$defs` を含めて返し、残った `$ref` を応答の中で辿れるようにする。
