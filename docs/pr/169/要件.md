# 要件

## 要望

- `write_docs` の `text_edits[].field`・`add_to`・`remove_from` のキー・`unset` の要素の `#` で始まる参照の型の項目のパスで、`x-key` の値に `[` `]` を含む配列の要素（`request[]` の `operations[].fields` など）と、`[` `]` を含む辞書のキーを指せる
- 指した要素の中の項目を、`[` `]` を含まない値の要素と同じ読み方（最初の要素・`#{順番}`・辞書のキー）で解決し、書き込む
- `[` `]` を含まない値を指す既存の書き方（`#functions[save].process`・`#functions[save#2].process`・`#notes[main.py の補足]`）は今までどおりに解決する

`未確定`: `[...]` の中の値に `[` `]` を含む要素を指す書き方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `[...]` の中で `[` と `]` の対応を数え、対応の取れた `[` `]` は値の一部として読む（`#request[operations[].fields].description`） | x-key の値をそのまま書ける。今の書き方の値はそのまま読める | 対応の取れない `[` `]` を含む値は指せない |
| B | `[...]` の中の `]` を `\]`（`\` を `\\`）で打ち消す（`#request[operations[\].fields].description`） | 対応の取れない `[` `]` を含む値も指せる | x-key の値を書き換えて渡す必要がある。`\` を含む今の値の読み方が変わる |

推奨: A

インターフェース定義の `request[]`・`response[]` の `name` は配列の `[]` の対応が取れた値で、x-key の値をそのまま書けるほうが指す側が書き換えずに済む。
