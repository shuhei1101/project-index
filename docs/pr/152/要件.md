# 要件

## 要望

- 有効な行の文書の ID が先の文書と重なり配信から除外したとき、`check_sync` の結果に除外した文書と先の文書の組を 1 件ずつ入れる
- `check_project` の索引の同期に件数と内訳を出し、起動時の検査（`log_source_check`）が警告のログに記載する。`status` の同期の件数と引数なしの `describe` の警告も、既存の同期のずれと同じく ID の重なりを含める
- ID の重なりの無い配信元では件数が 0 で、既存の検出の結果は変わらない

`未確定`: 同じファイルを 2 つの行が文書にして ID も重なるとき、`duplicate_files` と ID の重なりの両方に数えるか（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 両方に数える | 判定が `problems` の `duplicate_id` と 1 対 1 で単純 | 1 つの配置の誤りが 2 種類の件数に出る |
| B | 除外した文書と先の文書が同じファイルのときは ID の重なりに数えない | 1 つの原因が 1 件で出る | 同じファイルかの判定が増える |

推奨: B

同じファイルの重なりは `duplicate_files` が行の ID つきで原因を示しており、ID の重なりに重ねて出しても利用者の修正する箇所は変わらないため。
