## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元ごとの排他 | 同じ配信元のロックを、文書の MCP の実行スロットに入る前に、書き込みの期限までの残りの時間だけ待つ。握れなければファイルを書き換えずに `WriteDeadlineExceededError` を返却する | 待ち方は [要件](./要件.mark.md) の案 C。asyncio の書き込みの関所（`WriteGates`）を `run_docs` の前で握り、リポジトリの排他を握る呼び出しはリポジトリも同じ関所で待つ |
| 握る箇所 | `write_docs`・`delete_docs`・直コミットの書き込み（`_commit_locks`）の全てで同じ待ち方にする | 期限を持たない呼び出し（`limits` が `None`）は今と同じく待ち続ける |
| 既存の振る舞い | 排他の単位・握る順序（リポジトリの排他の後に配信元の排他）・握った後の処理は変えない | 破壊的変更なし |
| テスト | 同じ配信元のロックを握ったままにし、上限を超えた書き込みが `WriteDeadlineExceededError` で返ること、排他を待つ書き込みが実行スロットの本数を超えてもほかの配信元への書き込みと検索が待たないことを確かめる | 単体と結合 |
