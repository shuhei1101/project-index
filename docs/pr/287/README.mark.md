# 同じ配信元の書き込みのロックを待つ間に文書の MCP の実行スロットを持ち続けないようにする

## 概要

エージェントが、同じ配信元への書き込みが重なっている間も、ほかの配信元への読み書きを実行スロットの待ちで止められずに実行できるようになる。

## 背景

[#285](https://github.com/shuhei1101/project-index/issues/285) の不具合。[#282](https://github.com/shuhei1101/project-index/pull/282)（起点 Issue [#281](https://github.com/shuhei1101/project-index/issues/281)）のスコープ外の項目を切り出したもの。
`write_docs`・`delete_docs` は、同じ配信元の書き込みのロック（`SourceLocks`）の空きを、文書の MCP の実行スロット（`docs_executor`）を 1 本持ったまま上限なしで待つ。
同じ配信元への書き込みが重なると、ロックを待つ要求で実行スロットが埋まり、ほかの配信元への読み書きも待たされる。
#282 で改名の参照元の書き換えが短くなり待ちも短くなったが、ロックの待ち方そのものは変えていない。
