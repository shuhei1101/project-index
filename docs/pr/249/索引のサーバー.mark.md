## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 生成元の無い SKILL.md の削除 | 削除したスキルの `skill.path` の SKILL.md を削除する | `未確定`（決める段: インターフェース定義設計） |
| 生成した SKILL.md の見分け | 組み立てた SKILL.md が持つ生成元のコメント（配信元の直下からのエージェントフローのパス）で、エージェントフローから生成したファイルだけを削除の対象にする | `未確定`（決める段: インターフェース定義設計） |
| 直コミット | 削除した SKILL.md を生成物の変更として同じコミットに含める | IF-7 の `commit` の制約のまま |

削除の仕組みの論点:

| 案 | 内容 |
| --- | --- |
| A | `project-index skill-md` の生成のモードで、生成元のコメントが指すエージェントフローが `type: skill` で無くなった SKILL.md を削除する |
| B | `delete_docs` が、削除したエージェントフローの `skill.path` の SKILL.md をファイルの削除と一緒に削除する |

推奨: A

生成のモードは `write_docs`・`delete_docs` のどちらの後にも流れるので、`type`・`skill.path` を変えた場合と手で YAML を消した場合の前の SKILL.md も、同じ処理で消える。
