# 要件

## 要望

- 配信元の設定の `direct_commit` で、種類ごとに、直コミットで本文（`body_file` の列を持つ行の `@body`）を書き換えるのを断り、メタデータだけを許可することを決められる
- 断る種類の本文を書き換える次の直コミットは、ワークツリーを変えずに、断った種類・文書と理由を持つエラーで返却する。判定は、変更を適用した後に本文が書き換わる・移る文書（直接の操作の対象のほか、`rename` で書き換わる参照元と `replace_text` で置換した文書を含む）に対して行う
  - `write_docs` の `commit`（`set`・`text_edits` の `@body`、本文のファイルを新規作成する `create`、`replace`、`new_path` で本文のファイルを移す `rename`、参照元の `@body` のリンクを書き換える `rename`、`fields` に `@body` を含むか `fields` を省いた `replace_text`）
  - `delete_docs` の `commit`（行と一緒に本文のファイルを削除する）
  - 書き込みの API（画面のサーバーからの直コミットの書き込み）の書き込みと削除
- 断る種類でも、本文を変えずにメタデータの列だけを書き換える直コミットは今と同じく受け付ける
- 断る指定を記載しない種類と、`commit` を指定しない `write_docs`・`delete_docs` の振る舞いは今と変わらない
- 本文の直コミットを断る指定は、`direct_commit.kinds[]` の要素に、文字列のほかに `{id, body: false}` のオブジェクトも受け付ける形で記載する。今の `direct_commit.kinds[]` の文字列の記載方法は、そのまま受け付ける
