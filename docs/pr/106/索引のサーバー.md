## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| アウトラインの取り出し | 範囲のファイルごとに、ファイルが既に持つ説明・見出し・サイズ・コードブロックの割合と言語・リンクの数・関数名・クラス名・import を JSON で出す CLI のサブコマンドを加える | 段階 2 で足りるかの判定と理由も出力に含める |
| 変わったファイルの一覧 | 確認の時点の記録（無ければ管理用の YAML の最終変更）から今までに中身が変わったファイルを、作業ツリーの未 commit の変更を含めて出す CLI のサブコマンドを加える | Git 管理外は変更日時で比べる |
| 置き場所 | MCP のツールにせず、setup が既に呼ぶ `project-index` の CLI のサブコマンドにする | `未確定`（決める段: インターフェース定義設計）。案と推奨は下の表 |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `project-index` の CLI のサブコマンド | setup が既に `files` を呼んでいて、同じ入口とファイルの判定を使い回せる | - |
| B | setup スキルのフォルダのスクリプト | プラグインの中で閉じる | 管理用の YAML に記載するファイルの判定を二重に持つ |
| C | MCP のツール | setup の外からも呼べる | setup のときしか使用せず、ツールの一覧が増える |

推奨: A

管理用の YAML に記載するファイルの判定を `files` と同じ実装で持てる。
