## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| Mermaid の図 | 種類を規約『表し方の優先順位』の「伝えるものと図の種類」で選び、記法を mdmark の使い方集（`diagrams`・`flowchart-style`・`notation`）に合わせる | `sequenceDiagram` の置き換え先は `未確定`（[要件](./要件.md)） |
| 文・箇条書き | 同じ属性を持つ項目が 2 件以上あれば表にする。表の機能は mdmark の `tables` に合わせる | - |
| 文の削除と AI Slop | 規約『文章の書き方』の確認表と AI slop の単語の対応表で点検し、knowledge のスキル `text-review` をファイルの単位で回す | 定める内容（入出力・制約・期待値）は変えない |
| `description`（`lead`） | 「何を定め、どんなときに参照するか」の 1 文にし、規約『タグと用語の登録』の description の点検の表で点検する | 設計書の `lead` は `dev-docs.yaml` の `metadata.description` が指すキー |
| 本文の参照 | 生の文字の Issue 番号・文書のパスをタイトル付きのリンクに、他の設計書のパスを `{ID}#{項目のパス}` の参照にする | 各種類の `README.md` は `index.yaml` から生成するので、生成し直すだけにする |
| 書き込みと検査 | YAML の設計書は `write_docs` で書き込み、Markdown は `mdmark check` を通し、画面で描いて図の重なりを確かめる（mdmark の `diagram-check`） | - |
