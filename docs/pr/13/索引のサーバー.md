### Schema の移し方

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今のコピーを `schemas/{kind}.schema.yaml` へ `git mv` だけする | コピー元のバージョン（`ai-monitor-version.ini` の `v0.3.0`）と中身が一致したまま | `x-folder` などが移す前のパスを指したままになり、`visibility` が `共通.schema.yaml` の `visibility`（`user` / `developer`）と食い違う |
| B | ai-monitor#3307 の head の `schemas/` をコピーする | 移した後の置き場所・`doc_visibility`（`public` / `internal`）と一致する | コピーが未リリースのバージョンの中身になる |

推奨: B

移した後の文書の `visibility` を検証に合格させるには、`public` / `internal` を持つ #3307 の Schema が要るため。
