## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| cognitive complexity（`C901` を含む） | complexipy が 15 を超える 41 関数を、処理の工程ごとの関数に分割して 15 以下にする。分割した関数は元の関数と同じファイルに配置する | 分割の単位はモジュール構成設計で、設計書の `process` の工程に合わせて決める |
| `ANN401` | `Any` の引数・戻り値を、受ける値の型（`object`・`JsonValue` などの既存の型・`Protocol`）にする | 公開の関数の型が変わるときはモジュール構成の設計書の `args`・`returns` も修正する |
| `S101`・`PT018` | 型を絞るための `assert` を、条件の分岐と既存の例外の送出に置き換える | 送信する例外は、呼び出し元が既に受け取る型に限る |
| `DTZ011` | `date.today()` を、時刻のアダプターが返却する今日の日付に置き換える | 今の端末のタイムゾーンの日付を返すことを変えない |
| `N818` | 例外の名前を `Error` で終わる名前にする | 公開の `InvalidPrompt` は名前を変えると呼び出し元が変わるため、モジュール構成設計で扱いを決める |
| `BLE001`（`prompt_doc/render.py`） | 捕まえる例外を、呼び出した処理が送信する型に絞る | - |
| `# pyright:` の指定 | `reportUnknown...` の警告を、YAML・JSON から参照した値を `isinstance`・`TypedDict` で絞り込んで解消し（`cast` は使用しない）、指定を削除する | - |
| `complexipy-snapshot.json` | 違反を解消した後に削除する | `max-complexity-allowed` の 15 は変えない |
| 既存機能への影響 | MCP のツール・読み取り API・端末の設定の API・コマンドの入出力とエラーの文言を変えない | 単体・結合テストの期待値を変えずに全 pass させて確認する |
