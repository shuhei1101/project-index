## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| cognitive complexity（`C901` を含む） | complexipy が 15 を超える 41 関数を、処理の工程ごとの関数に分割して 15 以下にする。分割した関数は元の関数と同じファイルに配置する | 分割の単位はモジュール構成設計で、設計書の `process` の工程に合わせて決める |
| `ANN401` | `Any` の引数・戻り値を `object` にし、受け取った側で `isinstance` で絞り込む。`parse_compare_value` は `datetime \| float \| str` を返し、`to_tool_result` は結果の型を型引数 `T` にする | 公開の関数の型はモジュール構成の設計書の `args`・`returns` に反映済み |
| `S101`・`PT018` | 型を絞るための `assert` を条件の分岐に置き換える。起きない前提の箇所は `RuntimeError` を送出し、例外のハンドラーは受け取った例外を送出し直す | `assert` が送出していた `AssertionError` と同じく、呼び出し元は受け取らず 500 になる |
| `DTZ011` | `date.today()` を、標準ライブラリの `datetime.now(UTC).astimezone().date()` に置き換える（`admin/service.py`・`changes/service.py`・`read/nav.py`・`search/service.py`・`search/filters.py`） | 今の端末のタイムゾーンの日付を返すことを変えない |
| `N818` | 内部の `_Unresolved` を `_UnresolvedRefError` へ改名する | 公開の `InvalidPrompt` はインターフェース定義『プロンプトの文書の変換』が持つ名前のため改名せず、理由のコメントを付けて `# noqa: N818` を残す |
| `BLE001`（`prompt_doc/render.py`） | 部品の描画の `except Exception` に理由のコメントを付けて `# noqa: BLE001` を残す | 利用者のテンプレートが送る例外を絞れず、どの例外も組の注意書きにすることを設計書『プロンプトの文書の変換 / render.py』が決めている |
| `# pyright:` の指定 | YAML・JSON から参照した値は『共通 / narrowing.py』の `is_dict`・`is_list` で絞り込む。ruamel.yaml の `CommentedMap` は型引数を持たず値が Unknown になるため、`typings/ruamel/yaml/comments.pyi`（`py.typed` に `partial` を記載した部分的な型スタブ）で `dict[Any, Any]` の派生として宣言する。解消してから指定を削除する | `isinstance(value, dict)` は `dict[Unknown, Unknown]` に絞られるため使用しない。型スタブの解決は `## 実装` に記録 |
| `complexipy-snapshot.json` | 違反を解消した後に削除する | `max-complexity-allowed` の 15 は変えない |
| 既存機能への影響 | MCP のツール・読み取り API・端末の設定の API・コマンドの入出力とエラーの文言を変えない | 単体・結合テストの期待値を変えずに全 pass させて確認する |

## 実装

| 項目 | 内容 |
| --- | --- |
| 型スタブの解決 | `typings/ruamel/yaml/` に `py.typed`（`partial`）と `comments.pyi` だけを置き、`reveal_type` を並べたファイルに `uv run pyright --verbose` を実行した（2026-11-12）。`CommentedMap.get` は `dict` の多重定義（`(key: Any, default: None = None, /) -> (Any \| None)` ほか）、`CommentedMap().ca.items` は `dict[Any, Any]` で、型スタブから解決された。型スタブに無い `ruamel.yaml.YAML`（`type[YAML]`）・`ruamel.yaml.error.MarkedYAMLError`・`ruamel.yaml.scalarstring.DoubleQuotedScalarString` は導入済みのライブラリへ戻って解決された。`--verbose` の出力は stubPath に `typings` を含むことだけを示し、モジュールごとの解決先は出さない |
| `YAML` の型スタブ | `ruamel.yaml.YAML` の `load`・`dump` も引数の型が Unknown になるため、`typings/ruamel/yaml/main.pyi` で使用する属性とメソッド（`load` の戻り値は `object`）だけを宣言した。`comments.pyi` と同じく、型スタブに無い名前はライブラリへ戻る |
| `cast` を使用した箇所 | `is_dict` で絞った YAML・JSON の辞書を、キーが文字列の辞書（`dict[str, Any]`）として渡す箇所（文書の内容・スキーマ・配信元の設定・フックの入力）。キーを `str()` に変換すると YAML の数のキーが変わるため、値を変えずに型だけを読み替える。ほかに、型スタブが Unknown の多重定義を持つ jsonschema の `iter_errors`・`check_schema`、`isinstance` で絞った `tuple` の要素 |
| 型が Unknown のライブラリの関数 | jsonschema の `extend` は型スタブに型が無いため、`vars(jsonschema.validators)["extend"]` を、検査器の型を返す関数として読む（`validation/markdown.py`） |
