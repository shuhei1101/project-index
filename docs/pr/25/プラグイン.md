## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `# pyright:` の指定 | 標準入力の JSON から参照した値を `isinstance` で絞り、`reportUnknown...` の警告を解消して指定を削除する | 標準ライブラリだけで実装することを変えない |
| `BLE001` | `except Exception` を、どの失敗でも終了コード 0 で戻るフックの最上位の 1 か所だけに残し、理由のコメントを付けて `# noqa: BLE001` を残す | 下の表の案 B |
| 既存機能への影響 | フックの標準出力・終了コード・サーバーへの依頼を変えない | 単体テストの期待値を変えずに全 pass させて確認する |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 送信される例外の型（`OSError`・`ValueError` など）に絞り、`# noqa` を削除する | 抑止が残らない | 想定していない例外でフックが終了コード 0 以外で終わる |
| B | 最上位の 1 か所の `except Exception` に、終了コード 0 で戻る理由のコメントを付けて `# noqa: BLE001` を残す | どの失敗でも終了コード 0 で戻ることを保てる | 抑止が 1 件残る |

推奨: B

設計書『セッション開始のフック』が、どの失敗でも終了コード 0 で戻ることを決めているため。
