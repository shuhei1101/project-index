# 要件

## 要望

- 配信元の設定の `documents[].search_exclude` に該当する文書を、次の 3 つのエンドポイントでどう扱うかを決め、決めた扱いで実装する
  - 読み取り API の文書の一覧（`GET /sources/{source}/docs`。dev-docs の画面のサーバーが文書の値・共通のキーとあわせて取得する）
  - 読み取り API の語での検索（`GET /sources/{source}/search`。dev-docs の画面の検索が呼ぶ）
  - 文書の MCP の `list_match_words`
- 既定の結果から除くエンドポイントには、除いた文書も返却する明示の指定を持たせ、指定した結果では除く条件に該当する文書をそれと分かるように返却する（`search_docs` の `include_excluded` と同じ扱い）
- `search_exclude` を記載しない配信元・行の結果は今と変わらない

`未確定`: 読み取り API の文書の一覧での扱い（決める工程: 単一ユースケース設計。画面に出る文書が変わるため、規約『ユーザー確認が必須な事項』のユーザーが読む・操作するものとしてユーザーへ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既定の一覧から除き、`include_excluded=true` を付けたときだけ返却する | 画面のサイドバーに `inactive` の文書が出なくなる | 画面のサーバーが一覧から取得している文書の値・共通のキー（`related` など）を、除いた文書の分は取得できなくなる |
| B | 一覧からは除かず、各文書に除く条件に該当するかの値（`searchExcluded`）を追加して返却する | 画面のサーバーが取得する値は変わらず、画面が表示を選べる | 画面で見えなくするには dev-docs の画面の変更が要る |
| C | 今のまま全ての文書を並べる | 変更が無い | 画面で `inactive` の文書を見分けられない |

推奨: B

画面のサーバーは文書の一覧で文書の値と共通のキーもまとめて取得しており、除くと除いた文書の分を別の呼び出しで取り直すことになる。
値を返却しておけば、画面の側で薄く表示するか隠すかを選べる。

`未確定`: 語での検索と `list_match_words` での扱い（決める工程: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既定の結果から除き、`include_excluded` を付けたときだけ返却する | `search_docs` の既定と同じ結果になり、用語の照合が `inactive` の文書を指さない | 除いた文書の用語を照合したい呼び出し元は指定を付ける |
| B | 今のまま全ての文書を返却する | 変更が無い | 画面の検索と用語の照合だけが `inactive` の文書を返し、`search_docs` と結果が食い違う |

推奨: A

`search_docs` の `term` と `list_match_words` は同じ関数で用語を集めるため、既定の扱いを統一すると、`term` で絞った検索と用語の一覧の結果が一致する。
