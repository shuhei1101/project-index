## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 引数 | `write_docs`・`delete_docs` に省略可能な `commit`（`commit.message` を必須に持つ）を追加する。省略したときは今と同じ | `atomic: false` と同時の指定は断る。`dry_run: true` では取り込み・コミット・プッシュをしない |
| 直コミットの設定 | 許可する種類・コミットするブランチ・上書きできるブランチ・種類ごとの呼べる作業場所を持つ | 配信元の設定の `direct_commit` と端末の設定の `sources[].direct_commit`（[要件](./要件.mark.md) の確定した内容） |
| 実行する場所 | 直コミットの設定のブランチを指す配信元のワークツリーで実行する。ワークツリーが無い・別のブランチを指す・読み書きの方法が `disk` の配信元は断る | クローン本体のブランチは切り替えない |
| 排他 | 取り込みからプッシュまでをリポジトリの単位の 1 つの排他で囲み、同じリポジトリの配信元への通常の書き込みも同じ排他で待たせる | 今の配信元ごとの排他（MOD-82）はプロセスの中だけで、同じリポジトリの別の配信元を守らない |
| 書き込みの前の確認 | 早送りで取り込んだ後に、HEAD がリモートの追跡ブランチと同じこと・書き込むファイルと生成物に未コミットの変更が無いことを確認し、違えば書き込まずに断る | 早送りで取り込めないときも断る |
| コミットの範囲 | 操作が書き込んだファイルと `generators[]` の生成物だけを `git add` してコミットする。書き換わるファイルの種類が全て許可した種類のときだけ進める | 改名・一括の置換で参照元の他の種類の文書が書き換わるときは断る |
| 秘密の値の検査 | 書き込みの前に、書き込む文書の差分の追加の行を検査し、見つかれば何も書き込まずに断る | project-index が持つ正規表現の規則で照合する（要件の確定した内容） |
| プッシュが断られたとき | コミットを取り消してファイルを戻し、取り込みから 1 回だけやり直す。2 回目も断られたとき・通信に失敗したときは、ワークツリーをリモートの追跡ブランチと同じ状態に戻して理由を返却する | 戻すのは、この呼び出しが書き込んだファイルと生成物だけ |
| 結果 | 今の結果に、コミットの SHA・プッシュしたブランチ・やり直したかを追加する | - |
| 期限 | 取り込み・プッシュの所要時間を、1 回のツールの呼び出しの期限（MOD-129）の中に収める | 値は非機能要件で決める |
| 既存機能への影響 | `commit` を省略した書き込み・削除の振る舞いと結果は変えない | 既存の結合テストを回帰で実行する |
