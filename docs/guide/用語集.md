# 用語集

配信元・作業中の配信元・種類（kind）・バージョンなどの用語

<!-- table: data -->

| 用語 | 意味 |
| --- | --- |
| 配信元 | `project-index.yaml` を置いたフォルダ 1 つ。project-index が文書を配る単位で、端末の設定の `sources[]` の 1 行が 1 つの配信元に当たる |
| 配信元の ID | 配信元の主キー。端末の設定の `sources[].id`（省略時は `project-index.yaml` の `name`）で、読み取り API のパス（`/sources/{source}/...`）と文書の MCP の引数 `source` に使う |
| 端末の設定 | `${XDG_CONFIG_HOME:-~/.config}/project-index/settings.yaml`。Git の外に配置し、配信元の一覧と権限・待ち受け・状態の配置先を持つ |
| 配信元の設定 | `project-index.yaml`。配信する文書・検査・変換・画面のタブとサイドバーの構成・説明を持つ。複数の YAML に分けると、端末の設定の `sources[].config` に並べた順にマージする |
| 作業場所 | エージェントが作業しているフォルダ（`cwd`）。権限の判定と書き込みの先を決める |
| 作業中の配信元 | 作業場所を含む配信元のフォルダのうち一番深いもの。`source` を省いた呼び出しが指す |
| scope | 配信元を使える作業場所の glob。`scope.read` は参照できる作業場所、`scope.write` は参照と書き込みができる作業場所 |
| 作業範囲の外 | 作業場所が `scope` に当たらない配信元。文書の MCP の引数 `outside_scope: true` で参考として読め、結果に「作業範囲の外（参考）」の表示が付く。端末の設定の `sources[].outside_read` が `false` の配信元は読めない |
| ワークツリー | Git の配信元の作業ツリー。配信元の設定の `worktrees` に当たるものだけを読み書きの先にできる |
| クローン本体 | ワークツリーでない、リポジトリの元の作業ツリー。Git の配信元では書き込まない |
| 文書 | 配信する 1 件の単位。`documents[].paths[]` に当たり `documents[].exclude[]` に当たらない 1 ファイル、または `records` の配列の 1 要素 |
| 種類（kind） | 文書の行（`documents[]` の 1 行）の ID。書き込みでスキーマと新しい文書の配置先を決める。検索ではメタデータの 1 つとして絞る |
| スキーマ | 種類ごとの文書の構造を定める YAML。書き込みで変更後の文書を検査する |
| 検査（validator） | 配信元が持つスクリプト。書き込みの前などに文書を検査し、違反の一覧を返す |
| 変換（converter） | 文書の YAML を Markdown にする処理。project-index は `converters[]` を指す種類だけを配信元のスクリプトで変換し、それ以外の種類のスキーマ駆動の変換は dev-docs の画面のサーバーが行う |
| 生成（generator） | 書き込んだ後に流す配信元のスクリプト |
| バージョン | 文書と端末の設定のファイルの内容のハッシュ（短縮）。`write_docs`・`delete_docs` と端末の設定の API の書き換えの `expected_version` に渡して、読んだ後の変更を検知する。端末の設定のものは、`version` キーの設定のバージョンと区別して「端末の設定の内容のバージョン」と呼ぶ |
| 設定のバージョン | 端末の設定と `project-index.yaml` の `version`。サーバーが参照できるバージョンと比べて、古い設定の配信元を検出する |
| リビジョン | 読む時点。ブランチ・コミット・タグを `ref` で指し、省くと `default_ref` |
| 会話キー | `session_id` と `agent_id`。同じ会話で一度返した内容を、2 回目から省くために使う |
| タグ | 文書の分類。1 つの文書に複数付き、検索の絞り込みと `group_by` に使う |
| 関連（related） | 文書が別の文書を指す参照。`type` に関係の種類を持ち、`trace_related` でたどる |
| 共通のメタデータ | 文書の種類によらず、検索・関連のたどり・画面が同じように読むキー。`id`・`name`・`description`・`tags`・`main_tags`・`related`・`status`・`visibility` とエイリアスのキー。行の `metadata` で、共通のキーごとに読む列の名前を決める（列名の対応）。書いていないキーは同じ名前の列から読む |
| エイリアス | 用語・文書の別名・コマンドなどを本文の語に当てるための語。`alias_type` を持つ documents の行の文書の `name` と `aliases` で、キーは alias-inject のスキーマに従う。`search_docs` の `term`・`list_match_words` と、文書の画面の本文のツールチップに使う |
| 管理用の YAML | YAML でない文書（ソースコードなど）のメタデータを `files[]` に 1 ファイル 1 行で持つ YAML。`records: files`・`body_file: path` の行で配信する |
| 文書の MCP | `/mcp` の 1 つの接続先で、7 つのツールを出す |
| プラグイン | Claude Code のプラグイン `project-index`。`.mcp.json`（文書の MCP・管理の MCP）・SessionStart と PreToolUse のフック・スキルを配り、ユーザースコープで入れる |
| 管理の MCP | `/_admin/mcp` の接続先で、`status`・`reload`・`restart`・`update`・`check_project`・`try_convert`・`write_nav` の 7 つのツールを出す。`127.0.0.1` だけで待ち受け、作業場所では絞らない |
| 移し替え | 端末の設定と `project-index.yaml` を、新しい `version` の書き方に書き換えること。`project-index migrate` が手順を古い順に当てる |
| 索引の同期 | 管理用の YAML の行と範囲のファイルが合っていること。管理用の YAML に無いファイル・ファイルが無い行・`metadata` の列が無い文書の件数が 0 なら合っている |
| プロンプト | LLM の呼び出し・フックの注入文・MCP の instructions・ツールの description の本文を、部品と変数の定義で記載する YAML。`content/prompts/` に 1 ファイル 1 プロンプトで置き、`project-index prompt-doc` が文書の画面で読む Markdown にする |
| 部品 | プロンプトの `parts[]` の 1 要素。`id`・`role`・`when` と、言語ごとの Jinja2 の本文（`texts[]`）を持ち、`when` が真の部品を並び順につないだものが注入する本文になる |
| 例の組 | プロンプトの変数に入れる値の組。各変数の `example` で埋めた「既定の例」と、`examples[]` の 1 要素。組ごとに部品を描画した結果を文書の画面に出す |
