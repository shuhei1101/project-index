# 会話の指摘を登録する

会話で利用者が AI に伝えた指摘を、ルール・用語・文書として登録する手順

スキル `/project-index:feedback` は、このページを文書の MCP で取得して上から進めます。
CLAUDE.md と Claude Code の記憶には書き込みません。

## 登録先の選び方

| 指摘 | 登録先 | 次の会話で有効になる場面 |
| --- | --- | --- |
| ファイル・ツールを触るときに守ってほしいこと | rule-inject（ルールの本文と索引のエントリ） | 該当するファイル・ツールを触る前に rule-inject が案内する |
| 単語の意味・言い換え・やめた言い方 | alias-inject（用語） | 入力・ツールの結果に単語が出たときに alias-inject が用語を追加する |
| 経緯・判断の理由・背景 | project-index（文書） | `search_docs` で検索して参照する |
| その会話の作業だけに当てはまる話 | 登録しない | - |

- 指摘ごとに、表の登録先を推奨にして選択肢を出す
- rule-inject・alias-inject が入っていない端末では、その登録先を選択肢に出さない（手順 2）

## 抽象化

案は、会話の具体（その日のファイル名・作業名・やり取り）を除外し、他の場面にも当てはまる決まり・意味・理由にする。

| 会話の指摘 | 案 |
| --- | --- |
| 「この README の表、列を増やさないで」 | ルール: 表に列を追加する前に、既存の列の値で表せないかを確認する |
| 「ここで言う『束』は Issue をまとめたもののこと」 | 用語: 束 = 同じタグの未着手の Issue を 1 つの作業 PR で流す単位 |
| 「SQLite にしたのは、端末ごとに 1 ファイルで済むから」 | 文書: 状態の保存に SQLite を選んだ理由 |

- 1 件の指摘を 1 件のルール・1 単語の用語・1 件の文書にする
- 用語は [メタデータを付ける基準](./メタデータを付ける基準.md) の `## エイリアス` の判定フローチャートで登録するかを決める

## 手順

1. 指摘を集める。
   - 今の会話の文脈から、利用者が AI に伝えた指摘（守ってほしいこと・単語の意味・経緯や判断の理由）を集める
   - 1 件も無ければ、登録する指摘が無いことを伝えて止まる

2. rule-inject・alias-inject が入っているかを判定する。

   | ツール | プラグイン | 端末の設定のファイル |
   | --- | --- | --- |
   | rule-inject | `${CLAUDE_CONFIG_DIR:-~/.claude}/plugins/installed_plugins.json` の `plugins` に `rule-inject@` で始まるキーがある | `RULE_INJECT_CONFIG` が指すファイルか、`${XDG_CONFIG_HOME:-~/.config}/rule-inject/settings.yaml` がある |
   | alias-inject | 同じファイルの `plugins` に `alias-inject@` で始まるキーがある | `ALIAS_INJECT_CONFIG` が指すファイルか、`${XDG_CONFIG_HOME:-~/.config}/alias-inject/settings.yaml` がある |

   - 両方があるときだけ入っているとみなす
   - 片方だけのときは、そのツールを選択肢に出さず、`/rule-inject:global-setup`・`/alias-inject:global-setup` で用意できることを 1 行で伝える。端末の設定のファイルは作らない

3. 置き場所と効かせる範囲を 1 回だけ確認する。

   | 質問 | 既定 |
   | --- | --- |
   | 置き場所（以降 `{place}`） | `~/.local/share/feedback/` |
   | Git で管理するか | 管理しない |
   | 効かせる範囲 | 全ての作業場所。今の作業場所だけにもできる |

4. 指摘ごとに、既存の登録を検索して案と登録先を確認する。
   - 登録先ごとに近い既存の登録を検索する。ルールは rule-inject の `list_rules`、用語は文書の MCP の `search_docs`（`source: "*"`・`term`）、文書は `search_docs`（`source: "*"`）で検索する
   - 近いものがあれば、[新しく作るか修正するかの判定](./新しく作るか修正するかの判定.md) で追加か書き換えかを決め、書き換えなら前と後の内容を並べて示す
   - 案（`## 抽象化`）と登録先（手順 2 で入っているものと、project-index・登録しない）を確認する
   - 利用者が自由記述で別の置き場所を指定した指摘は、その置き場所を `{place}` にして手順 5・6 を進める

5. 置き場所を用意する。`{place}` に配信元の設定が無いときだけ実行する。
   - 端末の設定の `clone` の値を `{clone}` と呼ぶ
   - `{clone}/templates/feedback/project-index.yaml` を `{place}/project-index.yaml` にコピーし、1 行目のタグを `{clone}/.venv/bin/python -m project_index --version` の番号に `v` を付けた値にする。alias-inject が入っていないときは、`terms` の行と `nav` の用語集のタブを削除する
   - `{clone}/templates/files.schema.yaml` を `{place}/schemas/files.schema.yaml` にコピーする。alias-inject が入っているときは、`{clone}/templates/feedback/terms.schema.yaml` と `terms.yaml` も `{place}/schemas/`・`{place}/` にコピーする
   - rule-inject が入っているときは、`{clone}/templates/feedback/rules.yaml` を `{place}/rules.yaml` にコピーする
   - 作ったファイルの行を、[配信元を登録する](./配信元を登録する.md) の手順 5 の登録前の配信元と同じく `{place}/files.yaml` に直接記載する
   - Git で管理するときは、`git -C {place} init` の後に作ったファイルを commit する
   - [配信元を登録する](./配信元を登録する.md) の手順 6 で、端末の設定の `sources[]` に `{place}` の行を追加する。`scope.write` は `{place}`、`scope.read` は効かせる範囲（全ての作業場所なら `/**`、今の作業場所だけならそのフォルダの `/**`）にする。Git で管理しないときは `storage: {type: disk}` も記載する

6. 登録先の設定に置き場所を登録する。
   - rule-inject: 端末の設定の、効かせる範囲が全ての作業場所なら `global.indexes`、今の作業場所だけなら `match` がその作業場所の `projects[]` の `indexes` に、`{place}/rules.yaml` の行が無ければ追加し、rule-inject の `reload_settings` を呼ぶ
   - alias-inject: 端末の設定の、同じく `global.repositories` か `projects[].repositories` に、`config` が `{place}/project-index.yaml` の行が無ければ追加する
   - 端末の設定のファイルを書き換える前に、同じフォルダに `{ファイル名}.bak-{YYYYMMDD-HHMMSS}` のバックアップを取る

7. 選んだ登録先に書き込む。
   - ルール: 本文を `{place}/rules/{英小文字とハイフンの名前}.md` に記載し、rule-inject の `write_index_entry` で `{place}/rules.yaml` にエントリを追加する。`paths` は効かせたいファイルの glob にする
   - 用語: 文書の MCP の `write_docs` で、配信元 `{place}` の `terms` の行に要素を追加する
   - 文書: 本文を `{place}/notes/{名前}.md` に記載し、`write_docs` で `files` の行に `path`・`name`・`description`・`tags` を追加する
   - 書き換えを選んだ指摘は、既存のルール・用語・文書を書き換える

8. 登録した内容を示す。
   - 指摘ごとに、登録先・置き場所・書き込んだファイルか文書の ID を表で示す
   - 置き場所を新しく作った・端末の設定に登録したときは、そのことも示す
