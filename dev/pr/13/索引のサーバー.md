## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| YAML の設計書 | `docs/{kind}/{ID}.yaml` へ `git mv` する。`アーキテクチャ図.yaml` → `docs/architecture/ARCH-1.yaml`、`非機能要件.yaml` → `docs/nonfunctional/NFR-1.yaml`、`分類/パッケージ.yaml` → `docs/module/MOD-1.yaml`、`project_index/__main__.py.yaml` → `docs/module/MOD-3.py.yaml`、`索引のサーバー.yaml` → `docs/config/CFG-1.yaml`、`テスト実行方法.yaml` → `docs/test-procedure/TP-1.yaml`、`開発コマンド.yaml` → `docs/dev-command/CMD-1.yaml` | 中身は変えず、`visibility: internal` だけを追加する |
| 種類のフォルダの目次 | `dev/設計書/{種別}/index.yaml` を `docs/{kind}/index.yaml` へ移し、`page` を移した後のファイル名にする。`モジュール構成/分類/`・`モジュール構成/project_index/` の目次は `docs/module/index.yaml` へまとめる。`外部API/`・`外部ライブラリ/` は目次だけを `docs/external-api/`・`docs/library/` へ移す | README は目次から生成し直す |
| 全体の目次 | `dev/index.yaml`・`dev/設計書/index.yaml` の行を `docs/index.yaml` へまとめ、行が種類のフォルダを指すようにする。`dev/index.yaml`・`dev/README.md`・`dev/設計書/index.yaml`・`dev/設計書/README.md` は削除する | - |
| Schema | `dev/テンプレート/` を削除し、ai-monitor#3307 の head（[d0dc700e7](https://github.com/shuhei1101/ai-monitor/commit/d0dc700e7)）の `schemas/*.schema.yaml` を `schemas/` へコピーする | 下の「Schema の移し方」の B。`schemas/conversions/` はコピーしない |
| 公開ドキュメント | `docs/はじめに/`・`docs/使い方/`・`docs/リファレンス/` を `docs/guide/` へまとめ、`変更履歴.md` を `docs/guide/変更履歴.md` にする。分類（はじめに・使い方・リファレンス）と `visibility: public` は `docs/guide/files.yml` の行に持つ | 上タブ `nav.project.yml` と分類のトップページは分類から作る |

### Schema の移し方

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今のコピーを `schemas/{kind}.schema.yaml` へ `git mv` だけする | コピー元のバージョン（`ai-monitor-version.ini` の `v0.3.0`）と中身が一致したまま | `x-folder` などが移す前のパスを指したままになり、`visibility` が `共通.schema.yaml` の `visibility`（`user` / `developer`）と食い違う |
| B | ai-monitor#3307 の head の `schemas/` をコピーする | 移した後の置き場所・`doc_visibility`（`public` / `internal`）と一致する | コピーが未リリースのバージョンの中身になる |

推奨: B

移した後の文書の `visibility` を検証に合格させるには、`public` / `internal` を持つ #3307 の Schema が要るため。
